## 한 줄 개요
[[띵동]] 레포의 결정 기록 문서 `docs/decisions.md`를 검색하는 RAG 검색기. 작업을 맡기기 전에 과거 결정(폐기안 포함)을 찾아보려고 만든 개발 도구이고, 제품(서버·대시보드·펌웨어·ML)과는 무관하다. 출처: github.com/park-taegeun/ddingdong · `tools/decisions-rag` · 커밋 `5dccdac`.

## 현재 상태
- 청크 1,331개 인덱스(원문 커밋 `e471052`)로 기준선 측정, 실험 5개(E1~E5), 확인 세트(held-out) 판정까지 끝났다. 실험은 모두 사전 등록 규칙상 **미채택**이고, 기준선(dense)이 그대로 기본값이다.
- MCP 서버(`mcp_server.py`, stdio · 읽기 전용)로 내놓아 Claude Code 같은 클라이언트가 decisions.md를 직접 찾는다. 서버는 검색·탐색만 하고 **답은 만들지 않는다**(답변 모델 호출 0, 답은 호출한 LLM 몫). 검색은 기준선 설정 그대로다.
  | 도구 | 입력 | 하는 일 | API 키 |
  |---|---|---|---|
  | `search_decisions` | `query`, `k`(1~10) | 의미 검색 결과(순위·점수·절 라벨·제목 경로·근거 표기 `<커밋>@L시작-L끝`·본문)와 "결과는 힌트" 안내 | 필요(질의 임베딩 1회). 없으면 도구 오류 — 다른 검색으로 몰래 바꾸지 않는다 |
  | `list_sections` | `contains` | 절 라벨을 문서 순서로(최대 200개) | 불필요 |
  | `get_section` | `section`, `offset` | 그 절과 하위 소절 청크를 8개씩 | 불필요 |
- 시연(2026-10-07, Claude Code): 질문 1개에 `search_decisions` 1회 + `get_section` 1회를 불렀다. 결과와 답의 근거 표기 9건을 커밋 원문의 줄 범위와 대조해 모두 일치했다. 시연 기록은 세션 기록 파일에서 스크립트로 뽑았다(손 편집 0).
- README의 등록 예시와 시연은 user scope(`--scope user`)로 등록했다. 이렇게 등록하면 상관없는 세션에도 끼어든다 → [[mcp-scope]]

## 설계
| 항목 | 결정 | 이유 |
|---|---|---|
| 원문 | `git show <커밋>:docs/decisions.md` — 작업 트리가 아니라 커밋에 고정 | 같은 커밋 + 같은 설정이면 같은 청크가 나온다(해시로 검사). 줄 번호는 늘 `<커밋>@L시작-L끝`으로만 쓴다 |
| 청킹 | 직접 짠 구조 인식 청커. 제목(`##` 카테고리, `###` 절, 줄 머리 `**(a)` 소절) → 목록 최상위 항목·문단·표·인용·코드 블록 단위 → 목표 글자 수로 묶는다 | 문서 구조 단위로 자르기 위해. 라이브러리 기본 분할기 대신 직접 짠 이유는 (이유 미기록) |
| 오인 방지 | 코드 블록 안의 `#`·`\|`는 구조로 보지 않는다. `### 5/12 …` 같은 날짜 제목은 절 번호가 아니다 | 실문서에 코드 블록 안 `## ` 6줄, 날짜 제목 3개가 있다 |
| 커버리지 | 청크는 원문 줄 조각으로만 만든다 | "비어 있지 않은 모든 줄이 어떤 청크에 들어간다"를 테스트로 증명 |
| 임베딩·벡터DB | `text-embedding-3-small`, Chroma 로컬 저장(익명 통계 끔, Chroma 기본 임베딩 모델은 받지 않음). 임베딩 본문 = 제목 경로 한 줄 + 본문 | 메타데이터는 임베딩·답변 본문에서 뺀다. 근거 표기는 모델이 아니라 코드가 메타데이터에서 붙이고, 모델 출력은 근거 청크 **번호**만 믿는다 |
| 답변 모델(평가용) | `gpt-4.1-mini-2025-04-14` 스냅샷 고정, 온도 0, JSON | 별칭은 가리키는 모델이 바뀔 수 있다. 버린 것: 현행 소형 추론 모델 — 쓰던 라이브러리가 온도를 조용히 1.0으로 바꿔서, 그런 설정은 거부하게 했다 |
| 비밀값 검사 | 인덱싱 전에 OpenAI 키·`Bearer` 긴 토큰·quick tunnel 주소를 센다 | 키·토큰이 나오면 인덱싱을 멈춘다. 터널 주소는 인덱스 본문에서만 가린다. md5 같은 16진 해시는 세지 않는다 |
| 개인정보 검사 | 개인통관고유번호·메일 주소·AWS 계정 ID·휴대폰 번호를 센다 | 인덱싱은 막지 않고 인덱스 본문에서만 가린다(원문 수정 0). 출력은 종류별 개수와 절 위치뿐 |
| 설정 해시 검사 | 설정 파일에 모든 손잡이를 적고, 하나라도 빠지면 실패(기본값 금지). manifest에 설정 해시·커밋·청커 버전·패키지 버전을 남긴다 | 질의할 때 해시가 다르면 거부한다. MCP 서버도 기동할 때 설정 해시·커밋·인덱스 위치·청크 개수와 해시를 대조해 하나라도 어긋나면 뜨지 않는다 |
| 비용 | 임베딩 전에 토큰 수를 출력하고 상한을 넘으면 멈춘다. 평가 실행은 예상 비용이 1달러를 넘으면 호출 없이 멈춘다 | 단가표에 모델이 없으면 실패(기본값 금지) |

## 평가 설계
- **사전 등록**: 결과를 보기 전에 시험지와 채점 규칙을 고정했다. 등록 문서·평가셋·평가 설정을 평가 코드 0줄 상태로 먼저 커밋하고 이후 바꾸지 않는다(v1 2026-10-07, v2 같은 날). 바꿔야 하면 새 파일을 만들고 두 세트 수치를 모두 남긴다.
- **문항 유형 5종** — v1 30문항
  | 유형 | 문항 수 | 정답 조건 |
  |---|---|---|
  | fact (사실) | 10 | 핵심 값이 맞으면 정답, 일부만 맞으면 부분 |
  | identifier (식별자) | 5 | 같음 |
  | reversal (번복된 결정) | 5 | 지금 상태를 답해야 하고, 폐기안을 답하면 오답 |
  | not_in_doc (문서에 없음) | 5 | "문서에 없다"를 밝히면 정답, 지어내면 오답 |
  | false_premise (틀린 전제) | 5 | 전제를 바로잡으면 정답, 받아들이면 오답 |
- **지표**: 검색은 Hit@3·MRR@10(not_in_doc 제외, n = 25). 답은 정답/부분/오답 3단계. 환각(not_in_doc에서 지어냄)과 과잉 거절(답이 있는데 거절)은 항상 같이 보고한다.
- **대조군**: random(기대치 ≈ 0), bm25(표준 라이브러리 구현, 한글은 음절 2-gram).
- **held-out(H1)**: 15문항(유형별 3). 정답 청크가 v1과 겹치지 않는다. 1단계(v1 검색)를 통과한 후보를 **확인할 때만** 쓴다.
- **블라인드 채점 + 사용자 확인**: 시트의 행 순서를 섞고 조건·모델 이름을 숨긴다. 시트 번호 → 조건을 잇는 열쇠는 별도 파일이다. 판정 칸에는 정답·부분·오답 세 단어만 허용한다. 실제로는 Claude가 1차 판정하고, 판단이 갈릴 수 있는 5행을 사용자에게 보여 확인받았다(사전 등록의 "사용자 블라인드 채점"과 달라진 점으로 기록).
- **일관성 점검**: 같은 문항·같은 답·같은 거절 여부인 행끼리 판정이 같은지 시트 안팎으로 센다. v1 130쌍, v2 189쌍 모두 불일치 0.
- **gold_removed 자기 검증**: 문항마다 정답 청크를 뺀 인덱스로 다시 검색하면 Hit@3가 반드시 0이어야 한다. 아니면 평가기 결함으로 보고 실행을 실패시킨다. 모든 조건에서 0이었다.
- 평가 질문·정답은 `docs/decisions.md`에 쓰지 않는다. 쓰면 질문이 자기 답을 검색하게 되어 인덱스가 오염된다.

## 결과
### 기준선 (v1)
- 검색 Hit@3: dense **25 중 6**(MRR@10 0.131), bm25 25 중 4, random 25 중 0.
- 답: 정답 9 · 부분 4 · 오답 17 (30문항).
- **오답 대부분이 검색 실패다.** 부분 + 오답 21건 중 19건은 답변에 쓴 상위 5에 정답 청크가 없었다. 답변 모델을 바꿔도 같았다.

### 실험 — 모두 미채택
| 실험 | 바꾼 것 | 결과 | 미채택 이유 |
|---|---|---|---|
| E1 | 취소선을 `[폐기]` 표시로 바꿔 임베딩 | Hit@3 6 → 6, reversal 정답 2 → 2 | reversal 정답 +1 이상이 조건이었는데 늘지 않았다 |
| E2 | dense + bm25를 RRF로 합침(하이브리드) | 정답 9 → 10, Hit@3 6 → 4 | 전체 Hit@3 +2 조건 미달, reversal Hit@3 2 → 0. 정답 +1은 4문항을 얻고 3문항을 잃은 결과다 |
| E3 | HyDE(가상 문단과 질문 임베딩 평균) | Hit@3 6 → 5 | 1단계(Hit@3 +2) 미통과 |
| E5 | 큰 임베딩(`text-embedding-3-large`) | Hit@3 6 → 8 | 1단계는 통과했지만 동점 규칙(MRR@10 0.209 < E4 0.226)에서 져 2단계에 가지 않았다. H1 성능은 재지 않았다 |
| E4 | 제목 목록으로 질의 재작성 | v1 Hit@3 6 → 8, H1 Hit@3 1 → 5, v1 정답 10 | **held-out에서 뒤집혔다.** H1 정답 8 < 기준선 9 |

- E4는 v1 검색과 H1 검색, v1 답변 조건을 모두 통과했는데, 확인 세트 답변에서 기준선보다 1문항 적었다. v1에서도 Hit@3 +2는 4문항을 얻고 2문항을 내준 결과였다(기준선 2위였던 정답 청크가 10위로 밀린 문항이 있다).
- E4 후보도 부분 + 오답 20건 중 16건이 여전히 검색 실패였다. 검색을 고쳐 정답 청크가 들어와도 거절하거나 폐기된 옛 값을 고른 경우가 있었다.

### 로컬 모델 비교 (사전 등록 밖)
같은 상위 5 청크 위에서 답변 모델만 바꿨다(노트북 1대 기준).
| 답변 모델 | 정답 · 부분 · 오답 | 과잉 거절 | 답변 시간 중앙값 | 비용 |
|---|---|---|---|---|
| gpt-4.1-mini | 9 · 4 · 17 | 11 | 0.973초 | 약 $0.03 |
| llama3.1:8b | 6 · 5 · 19 | 4 | 6.295초 | 0 |
| exaone3.5:7.8b | 7 · 2 · 21 | 11 | 6.275초 | 0 |
- llama는 거절이 적은 대신, 정답 청크가 없는 문항에서 지어낸 답이 많았다.
- 비용은 로컬 토큰 수 × 단가표로 낸 추정치다(v1 답변 합계 약 $0.10, v2 합계 약 $0.27). 청구액이 아니다.

## 핵심 결정
- **2026-10-07 — 평가를 사전 등록하고 결과 전에 커밋했다.** 왜: 결과를 보고 기준을 맞추지 않기 위해서다. 사전 등록에 없던 값(RRF 목록 깊이 50 등)은 결과 전에 커밋으로 고정하고 "달라진 점"에 적었다.
- **2026-10-07 — v2는 검색 쪽 실험(E3·E4·E5)으로 정했다.** 왜: ① v1 오답 21건 중 19건이 검색 실패였다. ② BM25 사전 진단에서 질문 문장으로 찾으면 정답 청크 순위 중앙값이 22위였고, 기대 답 문장으로 찾으면 20문항이 1위였다 → 질문의 일상 표현과 문서 용어가 어긋나는 것이 원인으로 보였다(진단). 기대 답은 정답을 보고 쓴 문장이라 상한일 뿐 시스템이 쓸 수 있는 방법은 아니다.
- **2026-10-07 — 확인 세트(H1)를 따로 두고, 1단계 통과 후보는 하나만 보낸다.** 순서는 Hit@3 → MRR@10 → E5·E3·E4. 마지막 순서의 이유: 질의마다 LLM 호출이 없는 쪽 먼저.
- **E1·E2·E3·E4·E5 모두 미채택, 기준선 유지.** 왜: 각 실험이 사전 등록 조항을 하나 이상 통과하지 못했다(위 표). "채택"은 사전 등록 규칙 통과만 뜻하고, 기본 설정 반영은 별도 판단이다. 버린 것: v1 검색만 보고 E4를 채택하는 길 — held-out에서 뒤집혔다.
- **MCP 서버는 답을 만들지 않는다.** 왜: 답은 호출한 LLM의 몫이고, 검색 결과는 힌트라 인용 전에 원문과 대조해야 한다. 키가 없으면 다른 검색으로 바꾸지 않고 도구 오류를 낸다. 버린 것: 서버 안에서 답변 모델을 부르는 방식.

## 한계
- 표본이 작다: v1 30문항(검색 25), H1 15문항(검색 12). 수치는 방향 판단용이고 일반화 주장을 하지 않는다. E4를 떨어뜨린 차이도 1문항(8 vs 9)이다.
- 실행 1회. 온도 0·seed 고정이어도 API 결과는 완전히 결정적이지 않다.
- 독립 채점자가 아니다: Claude 1차 판정 + 사용자 확인. 기준선 v1은 다른 회차에 채점했다.
- H1 15문항 중 10개는 v1과 같은 시기에 같은 작성자가 쓴 후보에서 남은 것이다. v1과 완전히 독립된 표본이 아니다.
- 적중은 정답 조각 문자열이 청크에 들어 있는지로 판정한다. 다른 청크에 같은 정보가 있어 정답 청크 없이 맞힌 경우가 있다.
- E4는 매 질의 프롬프트에 문서 제목 목록을 넣는다. 문서가 커지면 생성 비용이 늘어난다.
