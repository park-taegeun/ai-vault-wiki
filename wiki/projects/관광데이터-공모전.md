## 한 줄 개요
2026 관광데이터 활용 공모전에 낸 전통주 양조장 여행 웹 서비스다. 「찾아가는 양조장」 59곳을 중심으로 공공 API의 양조장·전통주 제품 정보를 모으고, 주변 관광지·맛집·숙소를 묶어 탐색·코스·페어링을 보여 준다. 나는 데이터 파이프라인을, 인증·유저는 팀원이 맡았다.

## 현재 상태
제출이 끝났다. 아래는 노션 기록의 마지막 시점(8/15)까지의 상태다.
- **데이터 원천**: 서비스에서 실제로 쓴 공공 API는 관광공사 2개 + 농식품부(aT) 2개다. 양조장은 [[찾아가는양조장-api]](59곳), 제품은 [[전통주정보-api]](1,215건), 주변 장소는 관광공사 「국문 관광정보 서비스」([[tourapi]])에서 왔다. 관광공사에 없는 숙소·식당은 [[kakao-local-api]]로 검증했다.
- **마스터 파이프라인**: raw 적재 → 정규화 → ID 채번 → 마스터 적재 → 조인까지 완료(2026-07-30, PR #2). 전체 검증 clean test 47개 통과. DB는 PostgreSQL(로컬은 도커 컴포즈로 PG 16).
- **제품→양조장 조인 커버리지 58/59**: 자동 조인 56 + 수기 보정 2. 제품이 안 붙는 1곳은 실제로 제품이 없는 곳이다 → [[이름-정규화-조인]], [[수기-보정-레이어]]
- **좌표 59곳 전부 확보**(8/9). 양조장–주변 장소 연결 14,437건, 실제 장소 10,279개.
- **조회 기능**: 지역·방문 정보·주종·도수 필터 동작(8/9). 도수는 원문("10%", "25, 40, 54", "14~16" 등)을 숫자로 정리했다.

- **빈 화면**: 소개도 체험도 없는 곳 21곳, 그중 특징 문장도 사진도 없는 곳 14곳이다. 이 14곳은 이름·주소·지도·술 목록·방문 방식만 남는다. 전화·홈페이지·카카오맵이 모두 없는 곳도 1곳 있다 → [[화면이-아는-만큼만-말하기]]
- **방문 방식**: 상시 가능 35·불가 15·정보 없음 9, 예약 가능 24·불가 4·정보 없음 31로 조합이 7가지다. 디자이너 규칙을 적용하면 예약 방문 24 · 상시 방문 가능 27 · 전화 문의 필요 8곳인데, 전화 문의 필요 8곳 중 2곳은 전화번호가 없다.
- **대표 주종**: 만드는 주종 수는 1종 25 · 2종 22 · 3종 9 · 4종 3곳이다. 우선순위 규칙을 그대로 적용하면 동점이라 화면을 열 때마다 바뀔 수 있는 곳 2곳, 청주가 카드에서 사라지는 곳 3곳이 생긴다(청주를 만드는 3곳이 모두 여러 종류를 만들어 청주가 순위 밖으로 밀림).
- **제품 설명**: 원본이 79자에서 문장을 끊는다(술 설명 366개 중 331개, 특징 문장 323개 중 93개). 마지막 마침표 뒤를 버리면 235개가 정리되고, 마침표가 없는 96개는 그대로 두거나 숨겨야 한다.
- **수상 뱃지**: 수상 문구가 있는 술 366개 중 77개, 여러 개 적힌 것 35개다. "대상"만 뽑으면 대회 이름의 "대상"에 걸리고, "최신 1개"로 하면 더 높은 옛 상이 잘린다.
- **그 밖의 원본 오류**: 판매 중단 표시가 있는 술 10개, 같은 술이 두 줄로 들어온 곳 6곳, 같은 체험인데 자료마다 금액이 다른 곳이 있다.
- **사진·추가 정보 문의**: 8/11 aT(한국농수산식품유통공사)에 활용 가능 여부를 문의했다. 문의 항목은 양조장 사진(59개소), 체험 프로그램 정보(프로그램명·내용·소요시간·비용·사진), 운영시간, 연락처, 제품(술) 이미지와, 출처 표시 문구 형식·공공누리 유형·크기 조정·자르기 가능 여부·사용 가능 기간이다.

### 주변 장소·페어링 실측 (8/9)
- 장소 구성(10,279개): 음식점 4,140 · 관광지 3,293 · 레포츠 1,324 · 숙박 539 · 문화시설 506 · 축제·행사 322 · 쇼핑 141 · 여행코스 14
- 관광지는 어디든 충분했지만, 5km 안 맛집이 없는 양조장 16곳(27%), 10km 안 숙소가 없는 양조장 14곳(24%)이었다. 그 14곳은 카카오맵에서 모두 숙소가 확인됐다 → [[kakao-local-api]]
- 페어링: 술 설명에 안주 정보가 있는 양조장 30곳(51%) 중 24곳(80%)이 5km 안에 어울리는 종류의 식당을 갖고 있었다. 안 되는 6곳 중 4곳은 "안주 없이 마셔도 좋다"는 설명, 2곳은 근처에 해당 종류 식당이 없었다.
- 도수 분포(제품 단위, 정정값): ~9도 359 · 10~14도 378 · 15~19도 189 · 20~29도 102 · 30~39도 40 · 40도+ 161. 제안 구간은 저 14도 이하 737 · 중 15~29도 291 · 고 30도 이상 201이고, 양조장 기준으로는 저 52곳 · 중 30곳 · 고 31곳이 걸린다.

## API 구조
백엔드는 `/api/v1` 아래 32개 엔드포인트다(명세 기준 31개 구현 완료, 1개 구현 제외). 이 중 9개(양조장 목록·상세·술 목록·필터 메타, 통합 검색·자동완성, 추천 양조장, 지도 장소 상세, 체험 목록)를 내가, 20개(인증·유저·최근 검색어·지도·코스)를 팀원이 맡았고 3개는 담당이 적혀 있지 않다.

| 묶음 | 엔드포인트 | 특징 |
|---|---|---|
| 인증 | 카카오 로그인 시작·콜백, CSRF 토큰 발급, 로그아웃, 약관 조회·동의 | 세션 쿠키 + `X-XSRF-TOKEN` 헤더. 상태를 바꾸는 요청은 로그인·CSRF 필요 |
| 유저·온보딩 | 현재 회원, 내 취향 조회·저장, 온보딩 완료 | 온보딩 완료 조건: 선호 주종 1개 이상 + 도수 구간 1개 |
| 홈·추천 | 홈, 추천 양조장, 추천 코스 전체, 양조장 중심 추천 코스 | 추천은 **필터가 아니라 정렬**: 주종 일치 2점 + 지역 일치 1점, 동점은 상호명 가나다순. 비로그인·온보딩 전에는 고정 목록 |
| 양조장 | 목록, 상세, 술 목록, 검색·목록 필터 메타데이터 | ID는 `BRW-xxx`. 같은 필터 안 복수값은 OR, 다른 필터끼리는 AND. 술 목록은 판매 중단·중복·원본 오류 제품을 뺀 뒤 센다. 필터 메타는 주종 6종·지역 8칩과 각 양조장 수(0건도 count 0으로 내림) |
| 검색 | 통합 검색, 자동완성, 추천 검색어, 최근 검색어 저장·목록·개별 삭제·전체 삭제 | 검색·자동완성은 조회 전용이고 기록은 저장 API로 따로. 최근 검색어는 회원당 최신 10개 |
| 지도 | 장소·마커(bounds), 장소 검색, 장소 상세, 추천 양조장, 수상 전통주, 지금 찾아보면 좋은 메뉴 | 좌표를 주면 거리순, 없으면 이름순. 장소 유형: 양조장·음식점·관광지·카페·숙소 |
| 구현 제외 | 양조장 체험 목록 | 체험은 상세 응답의 `experiences` 배열로 대신 |

### 양조장 중심 추천 코스
- 코스를 테이블에 저장하지 않고, 요청 때 양조장·주변 장소·관광공사 콘텐츠를 조합한다. `courseId`는 중심 양조장 ID와 같다.
- 목표 구성은 양조장 1 + 음식점 2 + 관광지 2 + 카페 2 + 숙소 2 = 최대 9곳이다. 카테고리마다 5km에서 찾고, 2곳이 안 되면 10km → 20km로 넓히고, 그래도 부족하면 전체 좌표를 Haversine 직선거리로 계산해 보충한다. 0곳이면 그 유형을 뺀다. 실제 도로 길찾기·경로 최적화는 범위에서 뺐다.
- 음식점 페어링: 술 설명에서 안주 키워드(전·파전·삼합·보쌈·한우·고기·회·치즈)를 뽑아 관광공사 음식점 세부 분류·장소명과 대조하고, 매칭된 음식점을 거리보다 앞에 둔다 → [[텍스트-키워드-태깅]]
- 검증: 이 API 테스트 7개, 전체 `./gradlew clean test` 383개 통과.

  - 왜: 두 API 사이에 공용 ID가 없어 조인 키가 이름 문자열이다. 원본이 갱신되면(찾아가는양조장 차기 등록 2026-08-08) 이름 조인이 깨질 수 있어서 이름→brewery_id 매핑을 고정했다 → [[이름-정규화-조인]]
  - 버렸다: 갱신 때마다 이름으로 다시 조인하는 방식.
- **자동값(AUTO)과 수기값(MANUAL) 분리** — 배치를 다시 돌려도 MANUAL이 남게 했다. 같은 갱신 위험 때문이다 → [[수기-보정-레이어]]
- **예약·방문 정보는 3-state (Y / N / 모름)** — 예약 방문 정보의 52%(31/59)가 비어 있었고, null을 N으로 접으면 "미입력"이 "불가"로 읽힌다.
  - 버렸다: 빈 곳을 "예약 필요" 같은 기본값으로 채우는 안. 데이터에 없는 걸 지어내는 거라 틀릴 수 있다 → [[화면이-아는-만큼만-말하기]]
- **개발 진행의 정본은 노션 '개발 트래킹' 한 페이지** — 상세 근거는 API 분석 페이지로 넘기고, 진행 상태는 이 페이지에서만 판단한다 → [[single-source-of-truth]]
- **골든 스냅샷은 재계산·수정 금지, 정정은 별도 주석으로** → [[대조-가드]]
- **DB: PostgreSQL** — (이유 미기록)
- **지역 칩: 명세 8칩 수용 (부산·울산 독립)** — (이유 미기록). 버린 안: API 분석이 권고한 6광역권(경상 통합) 유지. 분석은 부산·울산 탭이 각 1건뿐이라 빈 탭에 가깝고, 대구 0·대전 0인 다른 광역시와 기준이 어긋난다고 봤다.
- **청주 단독 탭 유지** — 명세를 수용했다(이유 미기록). 버린 안: API 분석이 제안한 약주 병합(청주가 조인분 5건·양조장 3곳뿐이라 단독 탭이 최소 규모라는 이유).
- **당일 견학·시음 필드 제거 (거의 확정, 8/2 재확인)** — 두 API에 해당 필드가 없다.
- **맛 태그는 자동 추출로 못 간다 (RED 판정)** — 특징 컬럼의 60.9%에 맛 표현이 없고 자동 상한이 39.1%다. 8/2에 상세 화면에서 맛 태그를 빼기로 했고, 8/15에 주종별 고정 문구(탁주 = 부드러움 식)는 가능하다고 다시 판정했다 → [[텍스트-키워드-태깅]]
- **도수 필터는 숫자 범위로 받는다** — 경계값이 바뀌어도 대응할 수 있게.
- **관광공사 데이터를 계속 핵심에 둔다** — 공모전 평가 1순위 항목이 "관광 데이터 활용"이라, 카카오맵을 병행하더라도 관광공사 데이터는 관광지·문화시설·레포츠·축제와 양조장 자체 정보(사진·상세) 매칭에 쓰는 구도였다. 카카오맵 병행 여부 자체의 결론은 원본에 없다 → [[kakao-local-api]]
- **카카오맵 영업시간은 저장하지 않고 링크만** — 카카오맵이 데이터로 제공하는 정보가 아니라 약관상 저장할 수 없다.
- **카카오 이미지 검색은 사진 출처로 안 쓴다** — 결과가 개인 블로그 사진이라 저작권상 쓸 수 없다 → [[공공누리]]
- **잘린 제품 설명은 생성해 채우지 않는다 (8/15)** — 없는 내용을 지어내는 것이고 술 설명이라 사실과 다르면 문제가 된다. 마지막 문장 경계에서 잘라내는 안을 제안했다. 대가는 내용이 짧아지고 96개는 자를 수 없다는 것.
- **좌표로 현재 주소를 알아내는 방법을 버림 (8/15)** — 좌표가 주소로 만든 값이라 새 정보가 생기지 않는다.
