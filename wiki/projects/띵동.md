## 한 줄 개요
띵동(Ddingdong)은 현관에 붙인 기기가 초인종·노크·화재경보 소리를 ML로 분류해 청각장애인의 스마트폰(카카오톡)으로 알리고, 방문자 사진과 방문자가 한 말의 자막까지 보내는 졸업작품이다. 컨셉은 "기존 알림이 '띵동'으로 끝났다면, 이 시스템은 누가 와서 뭐라고 했는지까지 알려준다"이다.

## 현재 상태
2026-10-18, 졸업작품 기록 94 기준이다.
- **서비스 모델**: 4차 재학습 후보(인내 15)로 **조건부 교체**를 결정했다. 시연 리허설의 화재 확인(사이렌형·겹침형 포함)에서 하나라도 놓치면 기존 모델로 되돌린다. 되돌림은 서버 기동 시 모델 경로 하나만 바꾸면 된다 → [[모델-교체-판단]]
- **분류 클래스는 4종**(초인종 · 노크 · 화재경보 · 기타 소리)이다. "기타 소리"는 알림 전 분기에서 막혀서, 알림 문구까지 가는 것은 3종이다 → [[현관-소리-학습-데이터]]
- **자동 감지**(소리가 나면 기기가 스스로 판정)는 집에서 이어지는 것까지만 확인했다. 기준값·창 크기는 잠정이고, 기준 대비 여유(약 1.17배)가 얇은 문제는 미해결이다 → [[onset-detection]]
- **자막이 앞 구절만 오는 증상**: 녹음 길이 가설은 기각됐다. "말 사이 쉼에서 음성 인식이 끝난다"는 가설이 유력하지만 확정은 아니다 → [[asr]]
- **리셋 버튼 재부팅 시 사람 감지 센서 초기화 실패**: 원인을 아직 모른다. 펌웨어 수정은 정하지 않았고, 운영 우회(USB 재연결 + 첫 알림 카드의 거리 센서 칸 확인)만 있다 → [[vl53l5cx]]
- **센서 멈춤 보호 코드(1초)**: 기준을 1ms로 낮춘 시험 빌드로 경로만 확인했다. 실제 멈춤은 관측하지 못했다 → [[fault-injection]]
- **기기 상태(하트비트) 표시**: 서버와 화면만 준비됐다. 기기가 아직 신호를 보내지 않아 홈 카드는 항상 "꺼짐 · 기록 없음"이다 → [[화면이-아는-만큼만-말하기]]
- **서버 회귀 테스트 233개**(개발 보고 합산이고, 전체 재실행 확인은 아님). 라벨 순서 기동 가드, 펌웨어↔서버 대조, 응답 크기 예산, 데모 데이터 계약 테스트가 들어 있다 → [[대조-가드]]
- **시연 리허설 절차**는 초안이다. 판정 기준 칸(정할 질문 10개)은 비어 있고 날짜·장소도 미정이다.

## 문제 인식과 타겟
- 국내 청각장애인 등록 인구 441,835명(전체 장애인의 16.8%), 2024년 신규 등록 장애인 중 청각장애 31.7%로 1위다(보건복지부 2024년 등록장애인 현황).
- 청각장애인 26.1%가 1인 가구(약 11만 명)다. 시각 신호표시기 소지율은 0.3%, 보조기기를 사지 않은 이유 1위는 비용 부담(48.2%)이다(2023 장애인 실태조사).
- **핵심 타겟: 5060 중증 청각장애 1인 가구**. 중증 비율 17.7% × 1인 가구 26.1%로 약 2만 명을 추정했다(공식 교차 통계가 없어 비례 할당한 추정치).
- 청각장애인의 95.8%가 50대 이상이고, 50대 장애인 스마트폰 보유율은 97.1%다. 그래서 전용 수신기 없이 앱 알림으로 서비스할 수 있다고 봤다.
- 기존 국내 제품은 모두 "버튼 → LED/멜로디" 구조였다. "현관 부착형 + ML 소리 분류 + 앱 푸시 알림"을 동시에 갖춘 제품이 없다고 판단했다.
- 요구사항(2026-03-27 기획 발표): 24시간 감지, 감지 후 5초 이내 알림, ML 정확도 90% 이상. 이후 [[2단계-알림]]으로 1차 5초 / 2차 15초로 나뉘었다.

## 시스템 구성
```
[현관 기기: XIAO ESP32-S3 Sense]
  INMP441 마이크(I2S) ─ 2.048초 링 버퍼 → 자동 감지(onset)
  VL53L5CX ToF(I2C)  ─ 사람 검증 (화재경보는 우회)
  OV3660 카메라       ─ 2차 알림용 사진
        │ multipart (16비트 원본 바이트)
        ▼
[서버: Flask API v1]  /detect(1차) · /enrich(2차) · /notifications · /stats
  YAMNet fine-tuned 4클래스 → 판정 → 카카오톡 "나에게 보내기"
  사진 공개 URL 발급 · 클라우드 STT 자막
        │
        ▼
[React 대시보드] 3초 폴링, 접근성 우선(라이트 기본, aria-live)
```

## 시연 시나리오 v1
2026-05-09 설계, 2026-05-13 확정. 시연은 "발표"가 아니라 관람객이 돌아다니며 보는 **체험형 부스**다.
- **부스 3영역**: 좌측은 현관문 모형 가벽(인터폰 박스 안에 기기), 가운데는 멜로디가 다른 도어벨 4개·스마트폰·대시보드 노트북, 우측은 차별점과 통계 포스터.
  - 노크면 뒤에 MDF 보강재를 둔다. 폼보드 노크 소리가 학습한 실제 문 노크와 달라 분류가 틀어질 위험 때문이다.
- **진입점 3개** (자유 선택, 머뭇거리는 관람객에게는 ② 추천)
  1. 노크 + 발화: 사람 검증 → 5초 안에 1차 알림, 15초 안에 사진 + 자막 2차 알림.
  2. 초인종 등록 + 분리: 도어벨 하나를 3~5번 눌러 등록하면 다른 도어벨에는 알림이 없다 → [[초인종-유사도-검증]]
  3. 화재경보: 학생이 휴대폰으로 화재경보 음원을 재생한다. 사람 검증을 우회해 즉시 1차 알림 + 화재 대응 수칙을 보낸다.
- 2026-10-15에는 리허설 5단계(등록 → 등록 벨 알림 → 다른 벨 차단 → 사람 없음 차단 → 화재 알림)를 단계마다 1번씩 관통했다.

## 예산
- 재검토(2026-04-29): 기존 약 30,000원 → 약 160,000원. 보드 교체, VL53L5CX, 발열 대응, Plan B 예비, 케이스 재료가 늘었다.
- 실제 발주(2026-05-06): XIAO ESP32-S3 Sense Pre-Soldered 23,870원, INMP441 7,150원, VL53L5CX-SATEL 39,732원, 점퍼선 3종 각 935원으로 합계 73,557원. Plan B 부품(DevKitC-1, 외장 카메라)은 Plan A가 코드 수준으로 검증돼 취소했다(44,170원 절감).
- 서버: EC2 t3.small 업그레이드 월 +9,000원. 클라우드 STT는 단가 초당 0.5원, 추정 사용량 월 1,000~3,000원으로 기본 크레딧 100,000원 안에 들어간다.

## 핵심 결정
날짜 + 결정 + 이유. 세부 근거는 각 개념 페이지에 있다.

**기획·설계 (2026-03~05)**
- 2026-03-17 — 주제를 "실내 환경 이상 감지"에서 "청각장애인용 현관 소리 분류 알림"으로 바꿨다. 발표 피드백에서 타겟이 넓고 이미 구현된 제품이 많아 독창성이 약하다는 지적을 받았다.
- 2026-03-19 — 모델은 [[yamnet]] + Fine-tuning, TensorFlow + Keras로 정했다. 가볍고, AudioSet에 세 소리가 모두 있고, 공식 지원이 있어서다.
- 2026-04-07 — 서버 [[aws-ec2]] + [[nginx-gunicorn]] + [[flask]], 대시보드 [[vite]] + [[react]](3초 폴링)로 정했다. 실시간 알림은 카카오톡이 맡으니 대시보드는 로그 확인용으로 충분했다.
- 2026-04-07 — 하드웨어 3단계 필터링(PIR → ToF 1.5m → 소리 분류 + 유사도)을 설계했다. 센서 단계에서 먼저 걸러 서버 요청 자체를 줄이려는 것이었다. 처음 부품은 ESP32-WROOM-32, PIR HC-SR501, ToF VL53L0X였다.
- 2026-04-23 — 초인종 유사도를 "1D 펼침 + 코사인"에서 SP/DTW + cosine distance로 바꿨다. 누르는 길이가 다르면 벡터 위치가 어긋났다 → [[초인종-유사도-검증]], [[dtw]]
- 2026-04-27 — 사전 테스트로 pre-trained YAMNet 그대로는 쓸 수 없음을 확인하고 Fine-tuning을 핵심 과제로 정했다 → [[구현-전-사전-테스트]]
- 2026-04-28 — 화재경보는 공개 데이터 대신 AI Hub + 직접 녹음으로 대체했다. 공개 데이터의 "alarm"은 대부분 차량 사이렌이었다 → [[현관-소리-학습-데이터]]
- 2026-04-29 — 발표 피드백("킥이 필요하다")에 답해 **카메라 사진 + 방문자 음성 자막**을 추가하고, 알림을 1차(≤5초)·2차(≤15초 잠정)로 나눴다. 전체 흐름이 9~17초라 알림 한 번으로는 5초를 지킬 수 없었다 → [[2단계-알림]]
- 2026-04-29 — PIR + VL53L0X를 [[vl53l5cx]] 하나로 합치고 보드를 XIAO [[esp32-s3]] Sense로 바꿨다. 카메라 때문에 보드 교체가 필요했고, 8×8 멀티존 ToF 하나로 형체와 거리를 같이 판단할 수 있었다.
- 2026-04-29 — 범위를 줄이지 않았다(신규 추정 19~23주 대 가용 22주). 발표 피드백 1순위에 가장 강하게 답하는 안이었고, PoC 실패 시 사진만 남기는 강등안을 미리 준비했다.
- 2026-04-30 — 4개 영역을 1차 증거로 검증해 설계 3건을 즉시 바꿨다. EC2 t3.small, STT Google → Naver Clova Speech, 카카오 "나에게 보내기" → [[ai-산출물-검증]], [[aws-ec2]], [[asr]], [[kakaotalk-message-api]]
- 2026-05-06 — ToF 결과를 전송 차단 조건이 아니라 메타데이터로 보내고 서버가 클래스별로 분기하게 했다. 화재경보는 사람 없이 울려서 차단하면 누락된다.
- 2026-05-06 — 14개 영역 순회를 5번에서 멈췄다. 남은 항목 대부분이 개발 중 실측해야 정해지는 수치였다("분석을 멈출 줄도 알아야 한다").
- 2026-05-07 — GitHub repo의 `docs/decisions.md`를 최상위 기준 문서로, 노션은 보기 화면으로만 두는 운영 체계를 만들었다 → [[single-source-of-truth]], [[monorepo]]
- 2026-05-08 — 기관용 Wi-Fi(WPA2-Enterprise) 지원을 폐기하고 WPA2-Personal(집 Wi-Fi → 핫스팟)로 통일했다. 호환성이 사전 준비 일정의 최대 리스크였고 최종 시연은 어차피 핫스팟이다.
