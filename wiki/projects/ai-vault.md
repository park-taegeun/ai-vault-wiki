## 핵심 결정
- **한 볼트, 두 레포.** 공개 위키와 비공개 원본이 한 레포에 있으면 `.gitignore` 한 줄 실수로 원본이 공개될 수 있다. 루트 레포는 `_private/`를 통째로 무시하고, `_private/`는 별도 git 레포로 만들었다. git은 중첩 레포 안의 파일을 바깥 레포에 `git add -f`로도 넣지 못한다 — 규칙이 아니라 구조로 섞일 수 없게 했다. 분류 기준은 "애매하면 비공개, 공개 전환은 사람이".
- **① 규칙(soft)과 강제(hard)를 분리한다 — 팻말 vs 자물쇠.** CLAUDE.md는 어겨질 수 있는 부탁이다. 어기면 사고가 나는 규칙은 시스템이 막는다.
  | 시점 | 장치 | 막는 것 |
  |---|---|---|
  | 파일을 쓰는 순간 | PreToolUse 훅 가드 (exit 2면 차단) | 원본 수정, 공개 구역에 비밀값·개인정보 쓰기 |
  | 권한 | `settings.json` deny | push, `--no-verify`, `git config`, 가드·스크립트 자기 수정 |
  | 공개 레포 커밋 | pre-commit 훅 | 비공개 경로, 비밀값·개인정보, 공개→비공개 링크 |
  | 비공개 레포 커밋 | pre-commit 훅 | 살아 있는 API 키·토큰 |
  | 배포 | GitHub Actions | 공개 파일 전수 재검사, 실패 시 배포 중단 |
  push는 항상 사람이 한다. 가드는 패턴 모듈을 못 불러오면 막는 쪽으로 실패한다(fail-closed). 가드 메시지에 "규칙서 몇 장 위반"과 "우회하지 말고 보고하라"를 넣으면 Claude는 다른 길을 찾지 않고 멈춘다.
- **② 답이 정해진 일은 코드가, 판단이 필요한 일은 LLM이.** 링크 개수·끊긴 링크·고아 페이지·마감일·미처리 원본은 점검 스크립트가, 모순·중복·공개/비공개 분류는 Claude가 한다. Velog 수집도 LLM 없이 공개 GraphQL API로 한다.
- **③ 병렬로 쓰되, 공유 상태는 한 명만 고친다(single writer).** 서브에이전트는 초안만 쓰고 병합·목차·로그는 메인 혼자 고친다. 병렬 전에 용어집을 승인받아 페이지 이름을 고정한다. → [[nested-agent]]
- **④ "복리로 똑똑해진다"를 측정한다.** 골든 질문을 질문마다 새 서브에이전트에게 위키만 보고 답하게 해 채점한다. 자동화 2단계는 최근 14일 `/velog-wiki` 5회 이상 + correction(사람이 Claude의 판단을 고친 횟수) 1회 이하일 때만 검토한다. (2026-10-19 이 계획은 철회, 아래 참고)
- **손으로 해서 안정된 과정만 자동화한다.** 그래서 1단계는 수집만 자동화했다.
- **2026-10-19 — 자동화 2단계(정리까지 자동) 철회, "자동은 초안까지, 공개는 항상 사람"으로 확정.**
  - 왜: ① 준비도 지표는 "✅ 검토 가능"이 됐지만 실행 5회가 모두 하루에 몰린 백필이었다. 2단계가 맡을 일(하루 1~2편 조용히 정리)은 한 번밖에 해보지 않았다. ② 완전 자동으로 아끼는 건 명령어 한 줄뿐이고, 공개 레포라 결과 확인은 어차피 사람이 해야 한다. ③ correction 지표는 사람이 대충 볼수록 좋아진다(굿하트의 법칙: 지표가 목표가 되면 좋은 지표가 아니다). ④ 더 큰 위험은 공개 사이트의 모순 표시, 민감한 노션 자료 쪽에 있었다.
  - 버렸다: 2단계 전환, 지표를 고쳐 다시 2단계를 노리는 계획(YAGNI). 공개 글에서 사람의 확인은 없앨 비용이 아니라 설계상 남겨 둘 관문(human gate)이다.
- **2026-10-18 — 볼트를 보호 폴더 밖으로 이동 (`~/Documents/AI-Vault` → `~/AI-Vault`).**
  - 왜: launchd 자동 수집이 macOS TCC 보호에 막혔다(아래 트러블슈팅). 최소 권한 원칙에 맞고, git 레포를 iCloud와 동기화될 수 있는 문서 폴더에 두지 않는 편이 원래 안전하다(동기화 중인 `.git`은 깨지기 쉽다).
  - 버렸다: `/bin/bash`에 전체 디스크 접근 권한(1분이면 되지만 모든 백그라운드 bash에 마스터키를 주는 셈), 자동 수집 끄기(자동화 포기).
- **승인은 파일로 남긴다.** 시리즈별 공개 기준을 대화에서 승인했더니 새 세션은 "그 기준은 이 대화에 없다"고 보고했다. 기준을 `/velog-wiki` 스킬 파일에 고정하고, 기준에 없는 판단은 일단 비공개로 둔 뒤 묻고, 답을 받으면 "스킬 파일에 추가할 한 줄"로 제안하게 했다. 노션 반영 때는 공개 기준을 규칙서에 **먼저** 고정하고 시작했다.
- **평가 세트를 목적별로 나눈다.** 공개 10문항은 회귀 테스트(만점이 정상, 떨어지면 경보), 비공개 5문항은 성장 측정(넣기 전 낮고 넣은 후 높음), 여기에 과적합 확인용 예비 문항을 따로 둔다. 공개 세트 구성: 사실·트러블슈팅 4, 결정 이유 2, 이력 1, 시리즈 교차 연결 2, 위키에 없는 질문 1. 정답은 반드시 원본에서 확인한다. → [[llm-wiki]]
- **"왜"가 빠진 결함은 페이지가 아니라 규칙으로 고친다.** 기준선 29/30에서 0점 1문항을 추적하니 결정 이유가 빠져 있었고, 원본 26편과 대조하자 약 30곳이 같은 상태였다. 규칙서에 "결정은 무엇을 + 왜 + 무엇을 버렸나, 이유가 없으면 (이유 미기록)"을 넣고 핵심 결정 5곳만 보강했다. 세부 결정 20여 곳은 "위키는 요약" 원칙대로 두었다. 재평가 30/30, 나머지 9문항 회귀 없음.
- **노션 약 1,370개 md 중 152개만 1차 반영.** 졸업작품 94편 정리에 토큰 164만 개가 들었으니 전부 넣으면 10배가 넘는다. 파일마다 ① 다시 물어볼 일이 있나 ② 다른 지식과 연결되나 ③ 노션에 그냥 둬도 충분하지 않나를 물었다. 수업 필기 905개는 목록 카드 한 장으로만 남기고, Velog와 겹치는 노션 대시보드는 뺐다. 자료는 로컬 전용 / 비공개 / 공개 세 칸으로 나누고, 원본 창고(넣으면 수정·삭제 불가) 앞에 대기실(inbox)을 둬 분류와 비밀값 사전 검사(값은 출력하지 않고 개수·위치만)를 끝낸 것만 들여보냈다. 검사 결과 비밀값 0건, 개인정보 패턴 3건(업체의 공개 연락처, 예제 데이터).

  | 기계 검사(정규식) | 빠르고 매번 같은 결과 | 정해 둔 모양만 잡음 |
  | 의미 검사(AI가 읽고 판단) | "이 줄은 비밀번호를 적어 둔 것"이라는 문맥을 이해 | 느리고 가끔 틀림 |
  - 대응 순서(사고 대응): ① 가리기(원본 창고는 AI가 못 고치므로 사람이) → ② 범위 확인(두 레포 git 기록 전체 검색 0건) → ③ 교체 → ④ 재발 방지 규칙(패치 6.9) → ⑤ 새 규칙으로 전수 재검사(공개 0, 비공개 0).
- **2026-10-20 — 지우기보다 바꾼다(secret rotation).** 값을 가리던 처리 스크립트가 값을 터미널에 한 번 출력했다. 지우기는 "복사된 곳을 다 찾았다"는 가정에 기대지만, 교체는 옛 값이 어디 남아 있든 무력화한다. 이후 모든 검사·처리 명령은 값 대신 "파일:줄 (종류)"만, 실패할 때도 그렇게 출력한다.
- **2026-10-20 — 패치 6.9: 길이가 아니라 문맥으로 잡는다.**
  - 골랐다: "비밀번호 입력(…)" 같은 안내 문구 뒤, `password:` 같은 설정 키, DB 접속 명령의 `-p` 옵션, 계정 생성 SQL 자리를 잡는다. 자리표시자(`<REDACTED>`, `your_password`), 환경변수 참조, 코드 변수명은 통과.

  - 왜: 자동 수집(22:00)이 글을 먼저 저장하자 `/velog-wiki`는 "새 글 0편"으로 끝났다. Velog·백업·노션 대시보드·원본이 모두 207편으로 일치했는데 미처리 원본은 1이었다. 정합성(숫자가 서로 맞나)과 완결성(들어온 게 전부 처리됐나)은 다른 확인이다.
  | 방식 | 기준 | 약점 |
  |---|---|---|
  | 이벤트 기반(edge-triggered) | 이번 실행에서 새로 생긴 것 | 누가 먼저 가져가면 영원히 놓침 |
  | 상태 기반(level-triggered) | 지금 처리 안 된 것을 매번 계산 | 매번 전체 계산 비용 |
  - 골랐다: 상태 기반 + 마칠 때 미처리 수가 0인지 스스로 확인. 쿠버네티스 조정 루프(reconcile loop)와 같은 발상이다. 수집과 반영을 따로 만들면 그 경계에서 일이 샌다.

PreToolUse 훅 가드는 Write/Edit 호출만 보므로 셸 쓰기는 "쓰는 순간 검사"를 건너뛴다. 규칙서 문구를 세게 고치는 대신 가드가 위키 대상 `sed -i`, 리다이렉트(`>`, `>>`), `tee`, 위키 밖→안 `cp`/`mv`를 막게 했다. 막아야 할 명령 8개 차단, 허용할 명령 6개(읽기·검색) 통과를 확인한 뒤 적용. → [[claude-code-hook]]
