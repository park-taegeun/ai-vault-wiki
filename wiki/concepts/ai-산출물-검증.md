## 한 줄 정의
AI(코딩 에이전트·LLM)에게 맡긴 조사·코드·보고·권고를 그대로 믿지 않고, 실제 파일·실제 환경·원본 기록과 대조해 "그 근거가 무엇까지 증명하는지" 확인하는 [[띵동]]의 작업 원칙이다. 반대로 에이전트가 사람의 실수를 먼저 잡는 경우도 있어서, 지시하는 쪽의 판단도 검증 대상이다.

## 핵심 내용
- **1차 증거를 요구한다 (2026-04-30)**: "카메라와 I2S 마이크를 동시에 쓸 수 있나"를 부품이 오기 전에 확인하려 했다. 일반 검색은 단독 예제와 "이론상 가능" 글뿐이었다. 그래서 MCP를 명시해 조사를 맡겼다.

  | MCP | 역할 |
  |---|---|
  | [[context7-mcp]] | 공식 문서 조회 |
  | [[github-mcp]] | 실제 동작 코드·Issues·PR 검색 |
  | [[firecrawl-mcp]] | 벤더 문서 크롤링 |
  | [[sequential-thinking-mcp]] | 결론 단계에서 거짓 안심 차단 |

  프롬프트에는 "이론상 가능합니다 금지, 실제 동작 사례가 핵심, 실패 사례가 더 중요"를 넣었다. 드라이버 코드 근거와 작동 펌웨어 5건이 나왔다 → [[esp32-s3]]. 같은 방법으로 "막히면 설계가 무너지는" 4개 영역을 검증해 설계 3건이 즉시 바뀌었다 → [[vl53l5cx]], [[aws-ec2]], [[asr]], [[kakaotalk-message-api]]
- **코드 위임 시 자체 검증 3단계 (2026-05-07)**: 코드 작성·수정·빌드 설정 변경을 맡기는 모든 프롬프트에 넣는다. ① 효율성 ② 리팩토링(매직 넘버 상수화, 기존 컨벤션 일치) ③ 오류 방지(엣지 케이스, 메모리 누수, 동시성, 보안). 단계별 발견을 출력 끝에 따로 적게 한다.
- **사전 준비 기간에 쌓인 학습 (2026-05)**
  - 학습 13: 외부 출처를 인용할 때 전체 항목 수부터 적는다. 공개 글의 함정이 6개인데 4개로 알고 진행한 일에서 나왔다.
  - 학습 14: 인계 패키지의 추상 표현("컨벤션 일치")을 믿지 않는다. 실제 커밋을 보고 확인한다.
  - 학습 15: 공식 권장과 실제 패키지 상태를 따로 확인한다 → [[platformio]]
  - 학습 16: 위임 프롬프트와 기존 컨벤션이 충돌하면 기존 컨벤션이 우선이다. 기존 쪽이 명백한 오류일 때만 예외로 하고 사유를 남긴다.
- **AI가 박은 값과 진단도 검증 대상 (학습 17·19)**: 사람이 세운 가정뿐 아니라 AI가 결정 문서·위임 프롬프트에 박아 둔 값도 실제 코드·API·git log와 대조하기 전에는 확정이 아니다. 위임 프롬프트에 담긴 진단도 코드로 재검증한다.
- **오진에도 정도가 있다 (기록 41)**: "완전 오진"(코드로 반증되면 끝)과 "부분 오진"(방향은 맞고 메커니즘이 다름)은 다르게 다룬다. 후자는 접근을 살리되 실측한 메커니즘으로 고쳐 남긴다 → [[keras-savedmodel]]
- **확인의 네 층위 (기록 79)**: ① 얼마나 자주 보는가(관측률) ② 무엇을 검사하는가 ③ 검사가 실제로 실행됐는가 ④ **그 확인을 누가 하는가**.
- **판정 옆에 붙일 세 가지 (기록 73)**: 어디까지 확인했는가("없다"는 "내가 본 범위에 없다"일 수 있다), 무엇으로 확인했는가(실측·논증·문서 인용), 누가 확인했는가(만든 쪽의 자기 보고 vs 만든 적 없는 쪽의 재확인).
- **감사 등급의 뜻**: 에이전트 감사의 🔴 0은 "버그 없음"이 아니라 "재현으로 증명된 것이 0"이다. 권고의 근거가 비교표 일부 열에서만 왔는지도 확인한다. 안전 축부터 본다.

## 언제 쓰나 (상황 예시)
- 부품 구매·설계 확정처럼 되돌리기 비싼 결정 직전에 AI 조사를 쓸 때.
- 코딩 에이전트가 "검증 통과", "깨짐 0건", "갱신 필요 없음"을 보고했을 때. 무엇을 주입하고 무엇을 실제로 돌렸는지, 판단 근거가 된 파일을 직접 연다.
- LLM이 극적인 결론(붕괴, 확정)을 낼 때. 평가한 범위가 설계 전체인지 일부인지 되묻는다.
- 에이전트에게 정지 조건이나 "통과" 기준을 줄 때.

## 실습에서 배운 것 / 트러블슈팅
- **보고 요약 vs 실제 파일 (2026-05-12)**: 1차 판정은 "결정 문서 추가 갱신 없음"이었지만, 실제 파일을 처음부터 읽자 critical 1건(옛 추정값이 실측값과 충돌), moderate 2건(cross-reference 누락)이 나왔다. 다음 날에는 인계 패키지에 적힌 "기존 row"가 실제로는 없었다. 같은 원리가 다른 층위에서 반복됐다 → [[single-source-of-truth]]
- **AI 일반 패턴 vs 화면 직접 확인 (2026-05-16)**: 클라우드 기본 크레딧을 AI에 물었더니 "100,000원 / 100일"이었지만 실제 가입 화면은 "100,000원 / 3개월"이었다. 자동 결제가 켜져 있어 만료일이 8일 빠른 게 중요했다.
- **외부 서비스 진입 전 사전 검증 (2026-05-16)**: 학생 크레딧 프로그램 신청 메일을 보내기 전에 자격부터 확인했다. 거절 답변을 며칠 기다리는 손실이 더 컸기 때문이다. 공식 명단(32개 기관, 동적 로딩이라 Playwright로 확인)·기관 사이트·비공식 사례 세 출처가 모두 부재로 일치해 12분 만에 신청을 보류했다. 대조군을 같이 찍어 "검색 실패"와 "실제 부재"를 구분했다 → [[playwright-mcp]]
- **AI가 박은 값이 틀린 사례들 (2026-06-29~30)**: 위임 프롬프트의 DB ID 추정값, 결정 문서의 폴링 "2중"(실제 4중), "라이트 토큰을 새로 짜야 한다"(이미 완비), "필드를 새로 추가해야 한다"(이미 있음). 이전 인계 패키지의 "정정값"조차 자릿수가 맞지 않았다. 정정값도 다시 의심한다.
- **신뢰할 수 있는 리뷰어**: 일한 티를 내려고 문제를 부풀리지 않는다. 대시보드 정적 리뷰는 🔴 0건을 정직하게 보고했고 이후 TypeScript strict 에러 0건이 뒷받침했다 → [[react]]
- **안전 콘텐츠는 출처 등급을 강제한다**: "잘 찾아봐"로 맡기면 검색 상위의 아무 글이나 근거가 된다 → [[web-accessibility]]
- **진단이 반증된 사례 (기록 40)**: 빈 클립 크래시가 재발하자 "split이 가드 이전 폴더를 읽어서"라는 진단으로 수정을 맡겼다. 에이전트는 바로 고치지 않고 `git log -L`로 반증했고, 진짜 원인(stale 파일)으로 방향을 바꿔도 되는지 승인을 받은 뒤 수정했다 → [[현관-소리-학습-데이터]]
- **"검증 완료" 보고서도 다시 본다 (기록 41)**: "실제 모델로 export → reload 통과"가 실은 합성 더미 backbone을 넣은 검증이었다. 위임 전제 / AI 보고서 / 실 환경 실행 세 층위에서 오류가 따로 걸렸다.
- **감독 지점이 결과 → 과정 → 목적으로 앞당겨진다 (기록 42)**: 대시보드 미리보기에서 AI가 잡은 방향을 세 번 되돌렸다. 목적("발표 데모 자산" → "실 데이터 전 UI 미리보기"), 전제("mock 데이터 채우면 반영" → 에이전트가 repo를 실측해 4건 반박), 판단("0ms를 가짜로 채우자" → "실 계측을 앞당기자").
- **추측 대신 멈추는 것이 정답일 때 (기록 43)**: 파일 명명 규칙이 없어서 에이전트가 마커 설정을 멈췄다. 짐작했다면 에러 없는 잠복 버그가 됐을 것이다 → [[data-augmentation]]
- **우리 자신의 숫자도 검증 대상 (기록 44·45)**: 3개월 넘게 인용한 "분리 마진 8.42"는 다른 것을 재고 있었다. 반대로 LLM이 내린 "근거 붕괴" 결론은 2층 설계 중 한 층만 본 판정이었다. 극적인 결론일수록 다시 의심한다 → [[초인종-유사도-검증]]
- **가설을 "확정"으로 적지 않으면 데이터 앞에서 담담하게 고친다 (기록 46·47)** → [[2단계-알림]]
- **요약을 받으면 원본과 먼저 대조한다 (기록 51)**: 요약은 압축 과정에서 "정정했다"가 "완료했다"처럼 바뀌거나 단서가 떨어져 나갈 수 있다. 새 작업 전에 요약의 핵심 항목을 원본에서 한 줄씩 찾는다. 이번엔 불일치 0건이었다.
- **실행 도중 전제가 무너지면 멈추고 확인받는다 (기록 49)**: "무작위 결과 자리에 진짜 값만 넣으면 된다"는 계획이 코드 앞에서 무너졌다. 판단 로직이 뒤섞여 있어 값만 바꿀 수 없었다. 멈춰서 확인받은 뒤 분리하는 쪽으로 재설계했다 → [[대조-가드]]
- **숫자에 조건이 안 붙어 있으면 아직 근거가 아니다 (기록 55)**: ToF 판단선을 8에서 20으로 올리자는 권고의 근거 "37~55"는 목표 거리가 아니라 40~56cm에서 잰 값이었다. 막은 건 "그 상황이 내가 생각한 그 상황 맞아?"라는 한 번의 질문이었다 → [[vl53l5cx]]
- **문서의 미결 과제도 실물 확인 대상 (기록 56)**: 6일간 최우선 블로커로 올라 있던 문제가 파일을 열어 보니 없었다 → [[미결-실재-확인]]
- **전수 점검을 설계하기 (기록 57)**: "다 봐줘"로 던지면 얕게 훑고 "특별한 이상 없음"으로 닫힌다. 그건 점검을 안 한 것보다 나쁘다. 볼 축을 9개로 고정하고, 발견마다 파일과 줄 번호 인용을 강제하고, 인용을 못 대면 "확인 못 함" 칸으로 뺐다. 이 점검이 화면의 "사람 감지됨"이 고정 문자열이라는 걸 잡았다.
- **점검 결론도 가설이다 (기록 57)**: 점검이 스스로 찾아 놓고 등급을 낮춰 뺀 대안을 떼어 30분 실험했더니 코드 수정 없이 통과했다 → [[구현-전-사전-테스트]]. 결론과 발견을 분리해서 판정한다.
- **지시하는 쪽도 틀린다 (기록 59·62)**: 에이전트가 내가 지정한 망가뜨리기 변형이 무해하다고 짚었고([[fault-injection]]), "옛 숫자를 전부 최신 값으로 고쳐라"는 지시에서 다섯 곳 중 네 곳이 이력 서술이라 고치면 기록이 훼손된다고 짚었다([[single-source-of-truth]]).
- **"기존 기록과 다르다"는 보고를 원문 대조로 기각 (기록 70)**: 보고는 표현 차이를 내용 차이로 읽은 것이었다. 의심은 내 추론에도, 남이 가져온 보고에도 똑같이 건다.
- **분류 틀은 열고 불변식만 고정 (기록 72)**: 범주를 셋으로 지정했더니 가장 큰 덩어리가 어디에도 안 들어가 에이전트가 네 번째 범주를 만들었다. 핵심 불변식은 지켜졌다 → [[data-leakage]]
- **같은 눈은 같은 답을 낸다 (기록 73)**: 대량 편집 뒤 작업 세션은 "한글 깨짐 0건"이라 보고했다. 작업을 본 적 없는 새 세션에 읽기 전용으로 맡기자 1건을 더 찾았다(n=1).
  - 편집 오류가 한글을 비슷한 글자로 바꿔 저장했다(받침 차이 등). 한글 단어 안에 키릴 문자가 섞인 것도 눈으로는 같아 보였다. 통독·검색으로는 못 잡고 코드 단위 전수 대조로만 걸렸다.
  - 깨진 문자열을 설명하려고 그대로 인용했더니 그 문장이 새 오염원이 됐다. 이후엔 정상 표기·위치로만 설명했다.
- **확인 지시 첫 줄 가드 (기록 79)**: 확인 지시를 실수로 방금 편집한 세션에 붙여 넣었는데, 첫 줄에 "이 세션에서 편집한 이력이 있으면 즉시 중단"을 넣어 둔 덕에 세션이 스스로 멈췄다.
- **정지·통과에는 기준이 붙어야 한다 (기록 79)**: "예산의 10%를 넘으면 멈춰라"에 입력 크기를 적지 않아 에이전트가 최대 입력으로 재고 멈췄다. "전체 빌드 통과"도 환경 미지정이라 기본 환경 하나만 빌드한 것이었다. 14개 환경을 하나씩 지정해 돌린 뒤에야 "전부 빌드된다"고 말할 수 있었다.
- 결과를 받는 경로도 의심한다. 표에서 한 줄이 빠져 보였는데 실제로는 붙여넣기가 잘린 것이었다.
- **에이전트가 먼저 짚은 모순 (기록 87)**: 자동 감지 기준 66조합이 0개 성립한 이유를 분석을 맡은 에이전트가 먼저 짚었다 → [[onset-detection]]
- **읽기 전용 전 계층 감사 (기록 91)**: "알림을 못 받는 경로"로 증명된 것 0, 발견 20건(🔴 0 · 🟡 6 · 🟢 14). 테스트가 실제 방문자 사진 폴더에 쓰던 문제(실행마다 23장), "72시간 만료"가 파일을 지우지 않던 문제(5,387장 중 만료분 5,279장 정리) 등을 손봤다. "설정이 있다, 에러가 안 났다"는 동작의 증거가 아니다 → [[화면이-아는-만큼만-말하기]]
- **이긴 칸만 본 권고 (기록 94)**: 모델 교체를 권하는 설명이 "모든 축이 같은 방향"이라고 했지만, 근거 표에 새 모델이 진 칸(그중 2개가 화재)이 있었다. 결정 직전 표를 다시 펼쳐 바로잡았다 → [[모델-교체-판단]]
- 코딩 에이전트가 따로 돌린 테스트 실행도 외부 API 사용량에 잡힌다 → [[test-network-isolation]]
