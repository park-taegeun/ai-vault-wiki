## 한 줄 정의
ST의 멀티존 ToF(Time-of-Flight) 거리 센서다. 8×8 그리드(64 zone)의 깊이를 한 번에 재서 사람 형체와 거리를 같이 판단할 수 있다. [[띵동]]에서는 소리가 났어도 문 앞에 사람이 없으면 알림을 막는 "사람 검증"에 쓴다. 나중 글들은 이름 없이 "사람 감지 센서"라고만 부른다.

## 핵심 내용
- 시야각 65°, [[i2c]] 7-bit 주소 `0x29`, I2C clock 최대 1Mbits/s.
- 8x8 모드 최대 15Hz, 4x4 모드 60Hz. 띵동은 사람 형체를 64 zone으로 잡으려고 8x8 / 15Hz를 택했다.
- **RAM 기반 센서**: 전원이 켜질 때마다 펌웨어를 I2C로 올려야 한다(UM2884). 그 이미지가 MCU Flash에 들어가서, 실측 Flash 증가분 117KB 중 약 84KB가 센서 펌웨어였다 → [[esp32-s3]]
- **체온이 아니라 반사를 본다**: 빛을 쏴서 되돌아오는 시간을 잰다. 센서 위를 지나는 케이블, 택배 상자, 우산도 "앞에 뭔가 있다"가 된다. 그래서 사람과 물건을 가르는 움직임 단계가 필수다.
- 거리는 8×8로 나오지만 라이브러리의 움직임 값은 네 칸을 묶은 **4×4**로만 나온다. 사람과 물건이 같은 묶음 안에 겹치면 원리적으로 갈라낼 수 없다.
- **센서가 없으면 막지 않고 통과(fail-open)**: 센서가 깨어나지 않으면 기기는 거리 값을 보내지 않고, 서버는 값 없음을 "사람 없음"이 아니라 "판단할 수 없음"으로 읽어 통과시킨다. 그래서 센서 고장의 실제 모습은 "알림이 안 간다"가 아니라 **"사람이 없어도 알림이 간다"**다.

## 언제 쓰나 (상황 예시)
- 단순 거리값이 아니라 "사람 모양의 무언가가 가까이 있는가"를 저전력으로 판단해야 할 때.
- 카메라를 상시로 켜지 않고 사람이 있을 때만 켜는 프라이버시 게이트로. 화재경보는 이 검증을 우회한다 → [[2단계-알림]]

## 실습에서 배운 것 / 트러블슈팅
- **센서 선정 (2026-04-29)**: 처음 계획은 PIR(사람 감지) + VL53L0X(거리)였는데 이것 하나로 합쳤다. 단점은 가격과 멀티존 처리 알고리즘을 직접 짜야 한다는 점이었다. 실제 구매는 VL53L5CX-SATEL 39,732원.
- **사람 검증 단계적 알고리즘 (2026-04-30 채택)**: 전용 오픈소스는 찾지 못했고 ST 공식·Edge Impulse·논문 사례 5건을 근거로 삼았다. ST 공식 케이스 스터디(천장 2.4m 설치)는 NanoEdge AI 분류 98.14%, CNN 97.1%였다.
  - Stage A: 1m 안에서 8개 이상 zone이 동시에 걸리면 "사람 후보".
  - Stage B: Motion Indicator + zone별 임계값으로 정적 사물 무시.
  - Stage C/D(선택): NanoEdge AI 분류기, 1m 안에서 1.5초 이상 멈추면 진짜 방문.
  - ST의 98%는 천장 설치 기준이고 띵동은 벽면(눈높이 약 1.5m)이다. 벤치마크는 설치 조건이 다르면 그대로 믿을 수 없다.
- **라이브러리 사전 검증 (2026-05-07, 조건부 GO)**: SparkFun 라이브러리는 마지막 커밋이 2022년 11월이고 ESP32-S3 동작을 보장하지 않았다. 사용 사례 2건, open issue 0건. 워크어라운드로 I2C 1MHz, 정품/SATEL 모듈만 사용, 단일 센서 구성, Adafruit 폴백 라이브러리 명시를 정했다. 결과적으로 core 3.x와 충돌 없이 컴파일됐다 → [[platformio]]
  - 오래된 라이브러리는 "지원 명시 여부 → 실제 사용 사례 수 → 알려진 버그 → 대안 라이브러리" 순서로 확인하고 폴백을 미리 정해 둔다.
- **더미 코드 (2026-05-11)**: `tofTask`는 Core 0 / priority 3. `initToF()` 실패 시 task를 띄우지 않고 2회 retry + I2C bus scan. 카메라·마이크와 같은 "부품 부재 graceful" 패턴이다.
- **센서가 응답하지 않던 이틀 (2026-08-07)**
  - 증상: "버스에 아무 장치도 없음". 통신 속도 낮추기, 전원 추가, 예비 부품 교체 모두 그대로였다.
  - 원인 1: 단자 배열을 한 줄로 세어 읽었는데 실제로는 두 덩어리로 나뉜 구조였다.
  - 원인 2(진짜): 이 센서는 깨우려면 별도 단자 두 개를 켜줘야 한다. 자는 센서가 통신선 하나를 아래로 붙들고 있어 통신이 시작되지 않았다. 두 단자를 전원에 물리자 초당 15번 값이 들어왔다.
  - 범위를 센서로 좁힌 건 직접 만든 진단 도구였고, 마지막 조각은 제조사 자료가 줬다 → [[i2c]]
- **1단계 판단: 앞에 뭔가 있는가 (2026-09-09)**
  - 첫 측정이 "감지됨/없음"으로 깜빡였다. 굵은 케이블이 센서 바로 위를 지나고 있었고, 치우자 값이 7~10에서 0~1로 떨어졌다. 알고리즘이 아니라 측정 환경 오염이었다.
  - 그다음 판단 경계에서 5mm 차이로 판정이 뒤집히는 결함이 보였다. "3번 연속 같은 판단이 나와야 인정"하는 안전장치를 넣었다.
  - 판단선은 8을 유지했다. 20으로 올리자는 권고는 40~56cm에서 잰 값을 목표 거리 값으로 착각한 것이었다 → [[ai-산출물-검증]]

  | 거리 | 감지 칸 수 |
  |---|---|
  | 2.9m | 0 |
  | 1.2m | 0 |
  | 1.0m (목표 거리) | 10 |
  | 87cm | 29 |
  | 63cm | 40 |
  | 43cm | 56 |
  | 아무도 없을 때 | 0~2 |

- **2단계: 움직임 값 (2026-09-09)**: 네 상황을 각 30초 쟀다.

  | 상황 | 거리 감지 | 움직임 | 잡음대 |
  |---|---|---|---|
  | 아무것도 없을 때 | 0 | 0 | 12~24 (한 번 37) |
  | 상자 1m | 10~11 | 0 | 14~22 |
  | 가만히 서 있는 사람 1m | 9~42 | 0 | 18~42 |
  | 걸어오는 사람 | 10~64 | 1~5 | 45~544 |

  - 상자는 거리에는 잡히고 움직임은 0이었다. 가만히 선 사람은 상자와 구분되지 않았다.
  - 그래서 판단을 "지금 움직이는가"가 아니라 **"최근 몇 초 안에 움직인 적이 있는가"**로 바꿨다. 초인종을 누르는 사람은 걸어와서 누르고, 상자는 놓인 뒤 움직이지 않는다.

  ```
  존재 확인   여러 번 연속 맞아야 인정  → 잡음 억제
  움직임      한 번만 걸려도 유지       → 사건 보존
  ```
- **후보 기준값이 산술적으로 틀려 있었다 (기록 57)**: 후보 옆에 "잡음 상한 A와 사람 하한 B 사이"라고 적혀 있었는데 값이 B보다 컸다. 채택했으면 가장 약한 신호를 놓쳤다. 임계값을 넣기 전 실측표 다섯 줄을 전부 대입하는 절차에서 걸렸다 → [[구현-전-사전-테스트]]
- **센서 자체 판정값 채택**: 파생값은 사람이 경계를 정해야 한다. 센서가 직접 세어 주는 값을 써서 사람이 숫자를 정하는 자리를 줄였다.
- **화면 문구가 가짜였다 (기록 57·60)**: 대시보드의 "사람 감지됨"은 센서 값이 아니라 코드에 박힌 고정 문자열이었다. 서버에 실제 수신 경로를 만들자 그 문구가 사라졌다 → [[화면이-아는-만큼만-말하기]]
- **서버는 다시 판정하지 않는다 (2026-09-10)**: 기기 판정은 여러 프레임 이력이 필요한 시간축 판정이라 요청 한 건의 스냅샷으로 재구성할 수 없다. 서버가 다시 계산하면 답이 둘이 된다. 기기 판정은 그대로 믿고 수치는 증거로만 저장한다.
- **고장 방향을 기억으로 적었다가 거꾸로였다 (기록 90)**: 메모에 "센서가 죽으면 알림이 막힌다"고 적었으나 코드를 다시 보니 정반대(fail-open)였다.
- **리셋 버튼 재부팅 시 초기화 실패**

  | 측정 | 리셋 버튼 | USB 재연결 |
  |---|---|---|
  | 기록 90 | 4번 중 이상 2 | 3/3 정상 |
  | 기록 91 (같은 자리 번갈아) | 10번 중 이상 5 | 8번 중 이상 0 |
  | 합산 | 14번 중 7번 | 11번 중 0번 |

  - Fisher 검정 단측 p는 당일 약 0.029, 합산 약 0.007. 리셋이 서로 독립이라는 가정 위의 산술 근사다.
  - 진단 로그 빌드로 리셋 10번 → 이상 0. "고쳐짐"이 아니라 판정 불가다. 진단 코드가 부팅 타이밍을 바꿨을 가능성(관찰자 효과)이 남았다.
  - 옛 펌웨어·지금 펌웨어를 A·B·A·B로 5회씩 번갈아 쟀다(기록 93). A 10회 중 이상 2, B 10회 중 이상 1이었다. 관찰자 효과 가설은 약해졌을 뿐 기각되지 않았다.
  - 원인 가설: 리셋 버튼이 센서 전원을 끊지 않아 센서가 이전 상태에 걸려 있을 수 있다(미검증). 부팅 때 데이터선 단서는 [[i2c]] 참고.
- **운영 대응 (코드 수정 없음)**: 재시작은 리셋 버튼 대신 USB를 뽑았다 꽂는다. 재시작 뒤 첫 알림 카드의 "거리 센서" 칸이 채워졌는지 본다. 원인 해결이 아니라 우회이고, 결함이 있어도 사용자가 알아챌 수 있게 하는 장치다.
- **멈춤 보호 (기록 93)**: 센서가 동작 중에 멈추면 마지막 값에 갇혀 알림이 조용히 막힐 수 있다. 값이 1초(잠정) 넘게 갱신되지 않으면 거리 정보를 빼고 보내 초기화 실패와 같은 경로로 보낸다. 1초는 로그 882건의 프레임 간격(최소 0, 중앙 54, 최대 103ms)에서 정했다. 실제 멈춤은 재현할 수 없어 기준을 1ms로 낮춘 시험 빌드로 경로를 탔다 → [[fault-injection]]
- 모든 수치는 보드 1개, 실내 책상 위, 한 명 기준이다. 현관 벽·문틀 반사는 아직 검증 전이다.
