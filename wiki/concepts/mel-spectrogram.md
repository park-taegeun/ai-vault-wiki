## 한 줄 정의
소리 파형을 STFT로 시간×주파수 행렬로 만들고, 주파수축을 사람 귀 기준(멜 스케일)으로 다시 나눈 뒤 로그로 값 범위를 압축한 2D 표현이다.

## 핵심 내용
- **파형만으로는 부족하다**: 파형은 시간별 진폭만 보여 준다. "어떤 주파수가 얼마나 들어 있는지"는 보이지 않는다. 초인종과 노크를 구별하려면 주파수 정보가 필요하다.
- **푸리에 변환(FT)**: 복잡한 파형을 여러 사인파의 합으로 분해해 주파수별 에너지를 얻는다. 전체 신호를 한 번에 분석하면 시간 정보가 사라진다.
- **STFT**: 신호를 짧은 구간(window, 예: 25ms)으로 쪼개 구간마다 FT를 적용하고 시간 순으로 쌓는다. 결과가 스펙트로그램이다(가로 시간, 세로 주파수, 밝기 에너지).
- **멜 스케일**: 사람은 저주파 차이에 민감하고 고주파 차이에 둔하다. 멜 필터뱅크는 전체 행 수는 그대로 두고 저주파에 행을 더 많이, 고주파에 덜 배정한다.
- **로그 스케일**: 에너지 값 범위가 매우 넓어 모델이 큰 값에만 집중하게 된다. 로그를 씌워 범위를 압축한다.
- 같은 흐름이 Hershey et al. (2017) 3.1절에 STFT → mel 간격 주파수 bin → log 변환으로 정리돼 있다.

```
WAV(파형) → STFT → 스펙트로그램 → 멜 필터뱅크 → 멜 스펙트로그램 → 로그 → CNN 입력
```

- 소리 종류마다 에너지 분포가 다르게 보인다. 예: 한국 아파트 초인종은 400~800Hz 단음·빠른 어택·짧은 서스테인, 서양 차임벨은 복수 주파수 성분·긴 지속.

## 언제 쓰나 (상황 예시)
- 소리 분류 모델([[cnn]])의 입력. 2D 이미지라 이미지용 신경망 기법을 그대로 쓸 수 있다.
- 등록된 소리와 새 소리를 비교할 때 프레임 리스트 (T, n_mels)로 두고 [[dtw]]로 비교한다 → [[초인종-유사도-검증]] (128-bin, 로그 스케일).

## 실습에서 배운 것 / 트러블슈팅
- [[띵동]]에서 초인종·노크·화재경보를 구별하는 전처리로 로그 멜 스펙트로그램을 확정했다. 서버에서는 librosa로 변환한다.
- **1D로 펼치면 시간 정보가 위치에 묶인다**: 2초 고정 패딩에서 누르는 길이가 다르면 같은 소리도 다른 벡터가 됐다. 그래서 2D 프레임 + DTW로 바꿨다.
- **[[yamnet]]에는 멜 스펙트로그램을 넣지 않는다**: YAMNet은 raw waveform(16kHz mono)을 받아 내부에서 64-bin 멜 스펙트로그램을 만든다. 초기에 혼동했던 부분이다.
