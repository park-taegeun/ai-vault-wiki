## 한 줄 정의
입력 크기가 커질 때 알고리즘의 수행 시간(시간 복잡도)과 메모리 사용량(공간 복잡도)이 어떻게 늘어나는지 나타내는 척도다. 같은 일을 하는 알고리즘이면 보통 복잡도가 낮은 쪽이 낫다.

## 핵심 내용
### 복잡도 두 가지
- **시간 복잡도**: 특정 크기의 입력에 대해 알고리즘이 얼마나 오래 도는지 분석한다.
- **공간 복잡도**: 같은 입력에 대해 메모리를 얼마나 쓰는지 분석한다.

### 빅오 표기법
- 가장 빠르게 커지는 항 하나만 남기고 나머지 항과 계수는 버린다. 교재는 이를 함수의 "상한"만 나타낸다고 설명한다.
- 예: 연산 횟수가 `3N^3 + 5N^2 + 100000`이면 차수가 가장 큰 항만 남겨 `O(N^3)`.

### 문제 해결 4단계
1. 지문을 읽고 컴퓨터적으로 생각하기
2. 요구사항(복잡도) 분석
3. 해결 아이디어 찾기
4. 소스코드 설계와 코딩

출제자는 대체로 핵심 아이디어만 잡으면 코드가 짧아지도록 문제를 낸다.

### 설계 Tip: 연산 횟수로 시간 어림잡기 (교재 표기)
- CPU 기반 개인 컴퓨터나 채점용 컴퓨터에서 연산 횟수가 **5억**을 넘으면
  - C언어: 통상 **1~3초**
  - Python: 통상 **5~15초**
- 코딩 테스트의 시간 제한은 통상 **1~5초**다. 문제에 시간 제한이 적혀 있지 않으면 **대략 5초**로 보고 푸는 것이 합리적이다.
- 참고: 공식 기준은 없고 하드웨어·연산 종류에 따라 다른 경험칙이다. 널리 쓰이는 기준은 Python이 1초에 약 2천만~1억 번의 단순 연산을 처리한다는 것이다(PyPy는 더 빠름).

## 언제 쓰나 (상황 예시)
- 문제를 읽은 직후 입력 크기(N)와 시간 제한을 보고, 떠올린 풀이의 빅오가 제한 안에 들어오는지 먼저 따질 때
- Python으로 풀 때 같은 연산 횟수라도 C보다 훨씬 오래 걸린다는 점을 감안해 더 낮은 복잡도의 풀이를 고를 때
