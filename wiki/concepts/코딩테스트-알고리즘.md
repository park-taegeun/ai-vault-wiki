## 한 줄 정의
코딩 테스트에 자주 나오는 네 유형(그리디, 구현, DFS·BFS, 정렬)의 핵심 아이디어를 교재로 공부하며 정리한 페이지다. 시간 감각은 [[시간-복잡도]], 문법은 [[python-코딩테스트-문법]].

## 핵심 내용
### 그리디 (탐욕법)
- 지금 이 순간 가장 좋아 보이는 선택을 반복하는 방식이다.
- **정당성 검토가 핵심**이다. 매번 최선만 골라도 전체 최적해가 나오는지 따져 봐야 한다.
- 일반적인 상황에서는 그리디가 최적해를 보장하지 못하는 경우가 많다. 다만 코딩 테스트의 그리디 문제는 대부분 탐욕적 선택이 최적해가 되도록 출제되고, 그걸 추론해 내야 풀린다.

### 구현
- 머릿속 알고리즘을 소스코드로 옮기는 과정이다. 코딩 테스트에서는 "풀이는 쉽게 떠오르는데 코드로 옮기기 어려운 문제"를 가리킨다.
- 대표 유형: 알고리즘은 단순한데 코드가 매우 길어지는 문제, 실수 연산 후 특정 소수점 자리까지 출력하는 문제, 문자열을 정해진 기준으로 잘라 처리하는 문제, 알맞은 라이브러리를 찾아 써야 하는 문제
- **2차원 방향 벡터**: 시뮬레이션·완전 탐색 문제에서 상하좌우 이동을 표현할 때 자주 쓴다. (원본 노트의 그림 설명은 스크린샷이라 텍스트로 남지 않았다)

### DFS·BFS (그래프 탐색)
탐색은 많은 데이터 중 원하는 것을 찾는 과정이고, 대표적인 그래프 탐색 알고리즘이 DFS와 BFS다.

| | 스택 | 큐 |
|---|---|---|
| 순서 | 나중에 넣은 것이 먼저 나감 (LIFO) | 먼저 넣은 것이 먼저 나감 (FIFO) |
| 구현 | 리스트 | `collections`의 `deque` |
| 삽입 / 삭제 | `.append()` / `.pop()` | `.append()` / `.popleft()` |

- **재귀 함수**: 자기 자신을 다시 부르는 함수다. 종료 조건을 빠뜨리면 무한히 호출될 수 있다. 함수 호출은 메모리의 스택 프레임에 쌓이므로, 스택이 필요할 때 재귀로 구현하는 경우가 많다.
- 노트에는 재귀 바로 아래에 유클리드 호제법이 정리돼 있다: 자연수 A, B(A>B)에서 A를 B로 나눈 나머지를 R이라 하면, A와 B의 최대공약수는 B와 R의 최대공약수와 같다.
- **DFS (깊이 우선 탐색)**: 스택(또는 재귀)을 쓴다.
  1. 시작 노드를 스택에 넣고 방문 처리한다.
  2. 스택 맨 위 노드에 방문하지 않은 인접 노드가 있으면 하나를 스택에 넣고 방문 처리한다. 없으면 맨 위 노드를 꺼낸다.
  3. 2번을 더 할 수 없을 때까지 반복한다.
- **BFS (너비 우선 탐색)**: 가까운 노드부터 탐색하며 큐를 쓴다.
  1. 시작 노드를 큐에 넣고 방문 처리한다.
  2. 큐에서 노드를 꺼내고, 그 노드의 인접 노드 중 방문하지 않은 것을 모두 큐에 넣고 방문 처리한다.
  3. 2번을 더 할 수 없을 때까지 반복한다.

### 정렬

| 알고리즘 | 아이디어 | 시간 복잡도 (교재 표기) |
|---|---|---|
| 선택 정렬 | 남은 데이터 중 가장 작은 것을 골라 맨 앞과 바꾸기를 반복 | O(N²) |
| 삽입 정렬 | 첫 원소는 정렬됐다고 보고, 남은 데이터를 하나씩 알맞은 위치에 끼워 넣음 | O(N²), 최선 O(N) |
| 퀵 정렬 | 기준(pivot)을 정하고 그보다 큰 것과 작은 것의 위치를 바꿈. 기본형은 첫 원소가 pivot | 평균 O(NlogN), 최악 O(N²) |

- 삽입 정렬은 구현이 선택 정렬보다 조금 어렵지만 보통 더 효율적이고, 리스트가 거의 정렬된 상태라면 매우 빠르다.
- 퀵 정렬은 가장 널리 쓰이는 정렬 중 하나다. 교재는 병합 정렬과 함께 대부분 언어 정렬 라이브러리의 근간이라고 설명한다.
  - 참고: 실제 구현은 언어마다 다르다. Python `sorted`/`list.sort`는 Timsort(병합+삽입), Java는 원시형에 Dual-Pivot Quicksort·객체형에 TimSort, C++ `std::sort`는 보통 introsort(퀵+힙+삽입)를 쓴다. ([Python 문서](https://docs.python.org/3/howto/sorting.html), [Java Arrays](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/Arrays.html)) 이상적으로 분할이 절반씩 일어나면 높이가 logN, 각 높이에서 N번이라 N × logN이다.
- 원본 노트에는 세 알고리즘의 복잡도가 `O(N2)`로 적혀 있었다. 같은 노트의 `O(NlogN)` 표기에 따라 제곱으로 고쳤다 (정정).

### 결정과 이유
- 그리디로 풀지 말지: 최선 선택의 반복이 최적해를 보장하는지 먼저 검토한다. 일반적으로는 보장되지 않기 때문이다.
- 스택 대신 재귀를 쓰는 이유: 함수 호출 자체가 스택 프레임에 쌓이므로 스택 구현을 대신할 수 있다.

## 언제 쓰나 (상황 예시)
- 매 단계 최선의 선택이 전체 최적으로 이어지는 게 보이는 문제 → 그리디
- 풀이는 뻔한데 코드가 길고 실수하기 쉬운 시뮬레이션·문자열 처리 → 구현 (격자 이동은 방향 벡터)
- 그래프·격자에서 연결된 영역 찾기, 가까운 순서 탐색 → DFS·BFS
- 데이터가 거의 정렬돼 있으면 삽입 정렬이 유리

## 실습에서 배운 것 / 트러블슈팅
- 재귀는 종료 조건을 빠뜨리면 무한 호출로 이어진다.
