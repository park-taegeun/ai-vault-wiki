## 한 줄 정의
할 일·블로커 목록에 적힌 항목을 착수하기 전에, 그 문제와 그걸 막는 이유가 지금 실제로 존재하는지부터 확인하는 습관이다. "돼 있다"(기록·설정 상태)와 "되고 있다"(실제 작동)를 구분한다.

## 핵심 내용
[[띵동]]에서 겪은 "유령" 유형 (기록 63의 분류표):

| 유형 | 예 |
|---|---|
| ① 문제 자체가 없음 | 6일간 최우선 블로커로 들고 있던 문제가 존재하지 않았다 |
| ② 문제는 있었는데 기록된 적이 없음 | — |
| ③ 기록은 있는데 실물이 없음 | 경고 알림 "설정 완료"인데 수신자 0명 |
| ④ 없다고 기록됐는데 실재함 | "기록에 없는 항목"이 기록 문서에 멀쩡히 있었다 → [[single-source-of-truth]] |
| ⑤ 문제는 실재하는데 막는 이유가 유령 | "추가 설치 금지"로 3주 막혔지만 필요한 건 이미 다 깔려 있었다 |

- 비슷한 변형으로, 문제는 실재하지만 **해결 수단이 존재하지 않는** 경우도 있었다(아래 34일 사례).
- **"0건"과 "기록 없음"은 다르다.** 찾지 못했다는 말에는 어디까지 찾아봤는지가 붙어야 한다.

## 언제 쓰나 (상황 예시)
- 오래 이월된 할 일을 다시 잡을 때.
- "A를 하려면 B가 필요하다"고 적을 때. B가 정말 없는지 열어 본다.
- 기다리는 시간에 할 일이 없다고 느낄 때. 대개 목록을 안 만들어 본 것이다.

## 실습에서 배운 것 / 트러블슈팅
- **6일짜리 유령 블로커 (기록 56)**: "설정 주석 처리로 기능 활성"이라는 관찰 문장이 행동으로 읽혀 문서 4곳에 최우선 블로커가 생겼다. 해결 방법 세 가지를 정리해 고르기 직전, 파일을 열어 보니 문제 자체가 없었다. 확인 비용은 5분이 안 걸렸다 → [[ai-산출물-검증]]
- **34일간 들고 있던 불가능한 숙제 (기록 58)**: 노출된 키를 재발급해 옛 것을 무효화하는 일이 34일째 이월 중이었다. 관리 화면엔 새로 만드는 버튼만 있고 기존 걸 없애는 경로가 없었다. 키 하나만으로는 아무것도 못 한다는 걸 확인하고, 실제 관문 역할을 하는 다른 값을 새로 발급해 막았다. 기록은 "해결했다"가 아니라 "해결 수단이 없음을 확인하고 다른 관문으로 막았다"로 남겼다.
- **"돼 있다"와 "되고 있다" (기록 61)**: STT 자막이 비어 돌아온 원인을 세 번 추측해 다 틀렸다. 정답은 직접 걸어 둔 하루 한도 초과로, 콘솔 화면 한 장에 있었다. 정정이 반복되면 추론을 한 번 더 하지 말고 화면을 보러 간다. 70% 경고 알림은 켜져 있었지만 수신자가 0명이라 한 번도 작동한 적이 없었다 → [[asr]]
- **모순처럼 보인 두 숫자 (기록 61)**: 같은 항목에 자릿수가 다른 숫자 두 개가 적혀 있어 오기로 넘겨 왔는데, 하나는 시스템 최대치, 하나는 그때의 기본 설정값으로 둘 다 맞았다.
- **노트북만으로 할 수 있는 일 전수 조사 (기록 62)**: 문서·코드 전역의 미완·보류·"나중에" 흔적을 모아 9건을 찾았고, 그중 2건은 이미 해결된 유령이었다. 4건을 그날 처리했다.
- **단어 하나가 두 뜻 (기록 63)**: "자동 검사 도구를 들여와야 하는데 새 외부 부품 추가 금지 원칙에 걸린다"에서 「도구」가 프레임워크(새 부품)와 스크립트(이미 있는 라이브러리만 씀) 두 뜻을 가리켰다. 만들려던 건 스크립트였다. 3주를 막고 있던 건 문제가 아니라 단어 하나였다 → [[fault-injection]]
- **"기기가 있어야 한다"던 항목이 노트북 일이었다 (기록 66)**: 판정 기준 4개를 쪼개 보니 기기가 필요한 건 하나도 없었다(모델은 노트북에, 초인종 소리는 학습 데이터에, "사람 없음"은 요청 값으로). 다만 노트북 확인은 기기가 실제로 보내는 경로를 검증한 게 아니다.
- **"기록이 없다"는 유령이었다 (기록 70)**: "그날 테스트를 몇 번 돌렸는지 기록이 없다"고 믿었는데, 날짜별로 복원하자 세 날은 콘솔 숫자와 정확히 일치했다. 기록은 없던 게 아니라 찾지 않았던 것이다 → [[test-network-isolation]]
- **3주 이월된 질문을 좁혀서 닫음 (기록 72)**: "원본은 아직 감사하지 않았다"는 문장이 3주 동안 이월됐다. 원본 39GB 전수 해싱이 비싸서 못 한다고 여겼지만, 질문을 "이 15그룹의 동일성은 어디서 왔나"로 다시 쓰자 180개 파일·수백 MB로 같은 답이 나왔다 → [[data-leakage]]
- "이 저장소에 없다"와 "어디에도 없다"는 다르다. 확인 범위를 문장에 같이 적는다.
- **확신의 사다리 (기록 95)**: 문서의 문장을 `의도(코드 주석) → 후보(문서) → 확인됨(실측, 범위 명시)`로 등급을 매겼다. 마감 전, 실측 한 번이면 닫힐 질문을 골라 새 녹음 없이 저장된 데이터로 확인했다.
  - 누수 79건의 "정체 후보"(안내 멘트 조각)가 2×2 표 한 번으로 "확인됨"이 됐다 → [[data-leakage]]
  - 증강 "재현되게 만들었다"는 주석(의도)이 재실행 해시 비교로 "확인됨"이 됐다 → [[reproducibility]]
  - 올라가는 건 확인한 범위까지만이다. 범위를 적지 않은 "확인됨"은 의도와 다르지 않다.
  - 마감 전 정리도 "완료"로 뭉치지 않았다: 화면 확인 4개 통과 · 1개(사진 자동 재시도) 확인 불가, 연결 끊김 표시 5~6초는 체감값, 남은 작업 400개 중 노트북만으로 가능한 39개는 초안 계수, 사용량 대조(음성 인식 24회 · 실패 0 · 360초)는 실험 기록과 일치. 8개 파일 주석 정정(+38/−0)은 주석 뺀 코드 지문이 전후 같아 동작 변경 0이다.
- **고친 코드가 실제로 돌았는가 (기록 99)**: 사진 카드 중복을 고친 다음 날 14번 모두 카드가 1장이었지만, 그날 로그에 시간 초과가 0번이라 새로 넣은 분기는 현장에서 한 번도 돌지 않았다. "결과가 좋아졌다"와 "내가 고친 코드가 그 결과를 냈다"는 다른 문장이다. "고쳐 놓았다"(돼 있다)와 "고친 코드가 작동했다"(되고 있다)의 구분이 수정 확인에도 그대로 적용된다 → [[kakaotalk-message-api]]
  - 같은 글의 회고 세 가지: 현장에서 지키기 어려운 규칙("타이밍 맞춰 누르기")을 만들었다가 거둬들였고, 값을 가르는 원 로그를 계산하기 전에 직감으로 값을 먼저 권했고, 측정 로그 하나를 같은 이름으로 덮어써 그 구간은 원본과 대조할 수 없게 됐다. 이 규칙을 정말 따를 수 있는가, 값을 가르는 데이터를 봤는가, 기록을 덮지 않게 저장하는가로 돌아온다 → [[idempotency-key]]
  - 그 분기는 시연 날 처음 한 번 돌았다. 사진이 실제로 도착했는지는 확인하지 못해 "분기가 돌았다"까지다(기록 100).
- **끝나도 닫지 않은 16개 (기록 100)**: "부스 리허설에서 다시 판정한다"며 미뤄 둔 잠정값과 미결을 시연 기록에 대어 봤다. 닫는 조건은 세 가지를 모두 만족할 때로 정했다. 미리 정한 판정 기준이 있고, 시연 기록에 그대로 적용하면 결론이 나오고, 그 결론이 추가 결정이나 코드 수정을 요구하지 않는다.
  - 결과는 16개 중 닫힘 0이었다. 9개는 "잠정값 그대로 종료"로 남았다. 부스 리허설은 끝내 열리지 않았다.
  - 기준이 있던 두 항목은 재판정 조건에 걸렸지만 다음 단계가 사람의 검토라 닫지 않았다: 신뢰도 반올림 경계 경고 2건(둘 다 생활 소음, 보내고 말고가 갈린 건 0), 사진 대기 2.9초 시간 초과 1건.
  - 나머지는 기준이 없거나(생활 소음 비율 91.6%의 "과하면 다시 본다"), 판정할 재료가 없었다(등록 기준 0.20은 같은 벨 표시 없음, 전송 제한 2.5초 거절 1건은 보드 기록 없음).
  - "시연이 끝났으니 의미 없다"는 닫는 이유가 아니다. 재판정할 기회가 오지 않은 것도 확정의 근거가 아니다. 무엇을 못 쟀는지를 그대로 적고 끝냈다.
- **「됐다」의 네 층 (기록 101)**: 시리즈 전체를 돌아보며 정리한 사다리다.

  | 층 | 뜻 | 사례 |
  |---|---|---|
  | 연결됨 | 빌드가 되고 이어졌다 | 빌드 성공, 실보드에서만 드러난 문제가 있었다 |
  | 한 번 관통 | 끝까지 한 번 돌았다 | 시연 감지 1,584건(감지 수이지 알림 수가 아니다) |
  | 조건 바꿔 측정 | 한 변수만 바꿔 재 봤다 | 서비스 음량 대조, 콘솔 숫자로 한 테스트 대조 |
  | 기준 정해 판정 | 미리 정한 기준으로 결론을 냈다 | 미결을 닫는 조건, 16개 중 0개 충족 |

  - 한 번 끝까지 돈 것은 관통이지 검증이 아니다. 그래서 회차 수, 사람 수, 장소를 같이 적는다.
  - 숫자가 무엇에 기대는지도 다시 센다. 화재 9/10은 두 번째 감지에, 재학습 결과는 학습한 소리에, 1,584건은 "감지"라는 단어에 기대고 있었다(기록 100) → [[모델-교체-판단]]
