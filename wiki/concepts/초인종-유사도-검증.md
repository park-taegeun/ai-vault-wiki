## 한 줄 정의
분류 모델이 "초인종"이라고 한 소리가 정말 **우리 집** 초인종인지, 사용자가 미리 등록한 초인종 소리와 비교하고 문 앞 센서로 한 번 더 확인하는 [[띵동]]의 오탐 방지 설계다. 최종 비교 방식은 SP/DTW(FastDTW) + [[cosine-distance]]다.

## 핵심 내용
- **문제**: [[yamnet]]은 초인종이라는 종류만 맞힌다. 옆집 초인종이 울려도 "초인종 90%"로 알림이 간다. 2026-03-27 기획 발표 피드백에서 처음 지적됐고, 설치 시 사용자 초인종 소리를 등록받는 방향이 나왔다.
- **왜 중요한가**: 같은 아파트는 초인종 소리가 같은 경우가 많다. 옆집 초인종에 반응해 문을 열어 주는 일은 청각장애인에게 불편이 아니라 안전 위험이다.
- **등록**: 자기 집 초인종을 3~5회 누르면 ESP32가 녹음 → 서버로 전송 → [[mel-spectrogram]] 템플릿으로 저장. 이사하거나 초인종이 바뀌면 재등록한다.
- **비교 방식의 변화**
  - 처음(2026-04-07): 멜 스펙트로그램을 2초로 고정(길면 앞 2초, 짧으면 0 패딩)해 1D로 펼친 뒤 코사인 유사도 한 번으로 비교했다. 계산이 가볍다는 이유였다.
  - 폐기 이유: 위치 대 위치 비교라 초인종을 짧게/길게 누르면 같은 소리여도 "다른 소리"로 판정될 수 있었다.
  - 확정(2026-04-23): 2D 멜 스펙트로그램을 프레임 리스트로 두고 [[dtw]]로 가장 잘 맞는 프레임끼리 대응시킨다. 프레임 간 거리 함수는 코사인 거리라 등록 환경(조용한 실내)과 감지 환경(복도 소음)의 볼륨 차이에 둔감하다.
  ```
  등록 시: 녹음 → 멜스펙트로그램(2D) → SQLite 저장
  감지 시: 소리 → 멜스펙트로그램(2D) → FastDTW(거리 함수: cosine) → 유사도 점수
  ```
- **논문 근거**: PMC3745477(새 울음 DTW 비교). 야외 새 울음 2,116개에서 SP/DTW + cosine distance가 스펙트로그램 기반 방식 중 분리 성능이 가장 높았다. 평균 SNR 3.3dB로 복도보다 열악하고, "녹음 음량이 달라도 패턴으로 구분"이라는 문제 구조가 같다.
- **근본 한계와 센서 보완**: 같은 제조사 초인종이면 소리가 똑같아 임계값을 올려도 소리만으로는 못 거른다. 그래서 문 앞 센서를 겹쳤다.
  - 처음 설계(2026-04-07)는 PIR(사람 적외선) + ToF(VL53L0X, 1.5m 초과면 미전송)였다. 나중에 멀티존 ToF [[vl53l5cx]] 하나로 합쳤다.

## 언제 쓰나 (상황 예시)
- 분류 모델이 "종류"는 맞히지만 "누구의 것인지"는 구별 못 할 때. 개인 템플릿 비교와 물리 센서 조건을 겹쳐 오탐을 줄인다.
- 분류기가 화재경보를 초인종으로 잘못 분류했을 때 2차로 차단.

## 실습에서 배운 것 / 트러블슈팅
- **사전 테스트 (2026-04-27)**: 공개 WAV, 128-bin 로그 멜 → (T, 128) 프레임 → FastDTW + cosine, 템플릿 초인종 1개 고정 → [[구현-전-사전-테스트]]

  | 비교 쌍 | 평균 DTW 거리 | 최솟값 | 최댓값 | 표준편차 |
  |---|---|---|---|---|
  | 초인종 vs 초인종 | 4.233 | 0.742 | 5.735 | 1.639 |
  | 초인종 vs 노크 | 4.839 | 2.037 | 10.922 | 2.332 |
  | 초인종 vs 화재경보 | 12.651 | 3.042 | 21.451 | 5.897 |

  - 초인종 대 화재경보 평균 분리 마진은 8.418이었다.
  - 초인종 대 노크는 평균 차 0.606으로 크게 겹쳤다. 둘 다 단발성 충격음이라서다. 초인종/노크 구분은 YAMNet 몫이고 이 검증은 화재경보 오탐 방지에 집중하므로, 역할 분담이 맞다는 확인으로 봤다.
  - 처음 계획의 "유사도 0.8"과 실측 DTW 누적 거리는 척도가 다르다. 실제 임계값은 실측으로 다시 정해야 한다.
- **시연 진입점 ② (2026-05-09 설계)**: 멜로디가 다른 도어벨 4개 중 하나를 3~5번 눌러 등록 → 다른 도어벨은 알림 없음 → 등록한 도어벨은 1차 + 2차 알림 → 해제 후 재등록. 시연에서 가장 임팩트가 크다고 본 장면이다.
- **"분리 마진 8.42"의 정체 (2026-07-08)**
  - 발표의 차별점 "우리 집 초인종엔 반응, 옆집 것엔 안 함"의 근거로 이 숫자를 3개월 넘게 인용해 왔다.
  - 개체 구분을 처음 코드로 재보니 마진 **1.713**, 권고선 2.0 미달이었다. 5배 차이가 수상해 사전 테스트 코드를 소스 한 줄까지 추적했다.
  - 8.42는 소리 **종류**(초인종 vs 노크 vs 화재경보)를 가른 값이었다. 공개 데이터엔 "우리 집/옆집" 같은 개체 라벨이 없어 애초에 개체 구분을 잴 수 없었다. 틀린 숫자가 아니라 잘못된 자리에 놓인 숫자였다.
  - 두 값은 측정 대상, 특징(멜 128 vs 64), 정규화, 마진 정의가 모두 달라 직접 비교 자체가 무효다.
  - 1.713도 낙관적 상한이다. "같은 초인종"으로 묶은 데이터가 한 번의 녹음을 잘게 쪼갠 인접 조각이라, 다시 누를 때마다 생기는 변동이 빠져 있다. 같은 초인종을 여러 번 누른 공개 데이터는 없어서 직접 녹음이 유일한 방법이다.
- **2층 설계로 되짚음 (2026-07-09)**: 전날 판정은 옆집 구분을 소리 비교 하나로만 평가해 "근거 붕괴"로 결론냈다. 실제 설계는 2층이었다.
  ```
  1차 [거리 센서] 문 앞에 사람이 있냐   ← 주력 방어선
  2차 [소리 비교]  등록 시 보조 (등록된 초인종 소리와 얼마나 닮았나)
  ```
  - 근거는 물리적 차이다. 우리 집 초인종은 누른 사람이 문 앞에 서 있고, 옆집 초인종은 소리만 벽을 타고 새어들 뿐 우리 문 앞엔 아무도 없다.
  - 결론은 "2층 설계는 확정, 양쪽 다 검증은 예정"까지만 적었다.
- 오래 인용한 숫자일수록 "정확히 무엇을 잰 값인지"를 소스에서 추적한다. 나쁜 소식이 과장은 아니었는지(평가 범위가 설계 전체였는지)도 다시 의심한다 → [[ai-산출물-검증]]
