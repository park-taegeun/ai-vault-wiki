## 한 줄 정의
음향 벡터를 자연어로 풀지 않고, 학습한 projection으로 LLM 임베딩 공간에 옮겨 텍스트 임베딩 사이에 **soft token**으로 끼워 넣는 융합 방식이다. LLM 본체는 얼려 두고 projection만 학습한다.

## 핵심 내용
### 이 방향이 나온 이유
- 심박을 프롬프트 텍스트에 붙였을 때 LLM은 자기가 텍스트로 내린 판단을 합리화하는 데만 그 값을 썼다(LAB 11). 그래서 "통합은 표현 수준에서 해야 한다"는 가설이 나왔다. → [[sarcasm-detection]]
- 프롬프트 경로로 넣은 음향 정보는 판단에 반영되지 않았다(LAB 56). → [[음향-벡터-프롬프트-주입]]
- 임베딩 편차와 openSMILE 편차는 약하게만 겹쳤다(LAB 32). 그래서 명시적인 음향 수치를 별도 입력으로 넣을 근거가 생겼다.

### 왜 기존 embed_audio를 쓰지 않나 (LAB 57)
- [[audio-tower]]는 프레임마다 벡터를 만든다. 그래서 출력은 발화마다 길이가 다른 시퀀스다.
- [[어조-모듈]]의 벡터는 발화당 **고정 길이 요약 통계 1개**다. 입력 형태, 차원, 학습된 대응 관계가 모두 다르기 때문에 새 projection이 필요하다.

### 확정 설계 (LAB 57, 선행연구 StyleTalk·ParalinGPT·Dual Information SLM 조사)
- **soft token 수 k = 1**: 고정 요약 벡터 하나를 넣은 선행연구는 k=1이었다. 단순할수록 진짜 벡터와 placebo의 차이를 깨끗하게 해석할 수 있다.
- **projection 구조 = RMSNorm(scale 없음) → Linear(bias 없음)**: [[gemma-4]]의 embed_audio와 같은 구조를 차원만 바꿔 복제했다. 학습 대상은 `tone_proj.weight` 하나다.
- **주입 방식 = get_audio_features 교체**
  - gemma의 `masked_scatter` 배선을 그대로 재사용한다. 입력을 `[boa, audio_token, eoa]` = `[256000, 258881, 258883]`로 감싸 둔다.
  - 바깥에서 직접 주입하면 per_layer_inputs를 손으로 재현해야 해서, 틀려도 조용히 넘어갈 위험이 있다.
- **얼리는 부분**: audio_tower, embed_audio, language_model 모두 `requires_grad_(False)`로 둔다.
- **구현 함정 (transformers 5.9.0)**
  - masked_scatter는 dtype을 맞춰주지 않는다. projection 출력을 bf16으로 맞춰야 한다.
  - 프로세서는 wav가 없으면 audio_token을 넣지 않는다. id를 수동으로 넣고, 258881이 정확히 1개인지 assert로 확인한다.
  - 커스텀 kwarg를 만들면 generate의 2스텝째부터 죽는다. 기존 `input_features` 자리를 재사용한다.

### 학습 파이프라인 결정 (LAB 58)
1. **입력은 층2 63차원**: 층1에는 화자 신원이 실려 있어서(화자 프로브 정확도 0.958) 어조의 순수한 기여를 가린다. → [[어조-모듈-층2]]
2. **placebo는 미리 한 번 만들어 고정**한다. → [[placebo-control]]
3. **평가 데이터는 화자 단위로 분리**한다. → [[korean-emotion-speech-datasets]]
4. **학습 목표는 생성형 LM loss**다. 정답은 영문 감정 단어이고 loss는 정답 토큰에만 건다. 분류 헤드를 붙이면 새 파라미터가 생겨서 "학습 대상은 projection 하나"라는 설계가 깨진다.

## 언제 쓰나 (상황 예시)
- 숫자를 말로 풀어 프롬프트에 넣어도 LLM이 정보를 꺼내지 못할 때
- LLM 본체는 얼려 두고 외부 신호 하나의 기여만 깨끗하게 재고 싶을 때

## 실습에서 배운 것 / 트러블슈팅
- **소규모 스모크: 학습이 안 된 원인 3가지 (LAB 59)**
  - 증상은 loss가 2~8 사이를 무작위로 튀고, grad_norm이 가끔 212까지 폭발하는 것이었다. "어조 벡터가 약한가 보다"로 넘기지 않고 원인을 하나씩 확인했다.
  1. **EOS 토큰이 loss를 지배했다.** 토큰별 CE가 `<eos>` 12.69, K 8.40이었다. EOS를 빼자 loss가 5.99에서 2.86으로 떨어졌다. 무작위 기준선 ln15 ≈ 2.71 근처다.
  2. **학습 대상이 bf16이었다.** bf16의 machine epsilon은 약 3.9e-3이다. 그래서 0.02 크기 가중치에 1e-4를 더하는 업데이트가 반올림에 묻혀 사라졌다. projection만 fp32로 바꿨다.
  3. **학습률이 100배 부족했다.** 1e-4는 사전학습된 가중치를 미세조정할 때 쓰는 대역이다. 처음부터 학습하는 모듈에는 1e-3~3e-3이 맞아서 3e-3으로 올렸다.
  - 검증으로 64샘플 과적합 테스트를 했다. loss가 3.4510에서 0.0089로 떨어졌다. 배선은 처음부터 정상이었다.
  - 다만 64샘플을 외웠다는 건 "학습이 작동한다"까지만 증명한다. 텍스트만으로도 외울 수 있기 때문이다.
- **본학습: 낭독체 데이터 (LAB 60)**
  - 학습 때 보지 않은 화자의 4,082발화로 쟀다.
  - real은 20.14%, placebo는 22.76%였다. **델타 −2.62%p (McNemar p < 0.0001)**다.
  - real만 맞힌 발화는 232개, placebo만 맞힌 발화는 339개였다.
  - 프롬프트 경로도 같은 방향이었다. 그래서 문제는 전달 경로가 아니라 이 데이터 속 어조 정보 자체라고 판단했다. 데이터를 바꾼 이유다. → [[korean-emotion-speech-datasets]]
- **데이터 전환 후 2단계 검증 (LAB 61)**
  - 1단계: 선형 분류기로 정보가 **있는지** 봤다.
  - 2단계: LLM 융합으로 LLM이 정보를 **활용하는지** 봤다.
  - 1단계 결과
    - 텍스트와 음성의 감정 라벨이 어긋나는 구간에서 텍스트 정확도가 49.4%에서 30.7%로 무너졌다.
    - 같은 구간에서 어조 정확도는 29.0%에서 30.3%로 오히려 조금 올랐다.
    - 즉 어조는 텍스트를 대체하는 게 아니라, 텍스트가 무너지는 자리를 받쳐준다.
  - 2단계 결과 수치는 원글 이미지에만 있다. 분석은 [[어조-성분-분해]]에서 이어진다.
- **soft token을 4개로 늘리기 (LAB 63·67)**
  - 정보량(63차원)은 그대로 두고 통로만 넓혔다. projection 출력을 10240차원으로 만든 뒤 2560씩 4토막으로 나눠 네 칸에 넣었다.
  - 순위는 바뀌지 않았다.
    - k=1: placebo 39.42 > cross 38.31 > real 38.08
    - k=4: placebo 40.33 > cross 38.15 > real 38.02
  - 두 성분이 함께 커지기만 했다. 압축 손실 가설은 기각했다. **병목은 전달이 아니라 융합단이 정보를 활용하는 쪽**이다.
- **층1과 층2를 함께 넣기 (LAB 68·69)**: 입력을 126차원(층1 + 층2)으로 바꾸고 projection을 다시 학습했다. → [[어조-모듈-층2]]
- **LAB 57의 사전 경고**: 학습이 안 되면 20배 확대의 안정성과 초기화 스케일을 의심한다. 오디오가 무시되는 느낌이면 soft token 위치가 고정되어 생긴 붕괴를 의심한다.
