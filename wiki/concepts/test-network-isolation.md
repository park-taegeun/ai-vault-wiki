## 한 줄 정의
테스트가 실제 외부 서비스로 나가지 못하게 막고, **막은 사실 자체를 테스트 실패로 만드는** 격리 장치다.

## 핵심 내용
- 테스트 초록불은 테스트가 보려는 것만 알려 준다. 그 테스트가 바깥에 무슨 일을 하는지(돈을 쓰는지)는 알려 주지 않는다.
- 제품 코드가 외부 호출 실패를 정상 흐름으로 삼키면(예: 음성 인식 실패 → "자막 없음"), 연결을 **막기만 하는** 가드는 막았는데도 테스트가 합격한다. 다음에 또 새도 아무도 모른다. 그래서 시도 기록이 한 건이라도 있으면 실패로 끝낸다.
- 걸린 시간으로 외부 호출 여부를 판정하지 않는다. 판정은 서비스 콘솔(호출 수·사용량)로 한다.
- 일일 사용 한도를 낮게 걸어 두면 비용 상한이자 **관측 장치**가 된다. 서버를 안 돌린 날에도 사용량이 차면 설명되지 않는 호출이 있다는 신호다.

## 언제 쓰나 (상황 예시)
- 외부 API 사용량이 설명 안 되게 늘 때.
- 처음엔 가짜 응답으로만 쓰던 기능에 실제 호출 분기를 추가할 때. 테스트 코드를 한 줄도 안 바꿔도 옛 테스트가 진짜 호출자로 바뀔 수 있다.

## 실습에서 배운 것 / 트러블슈팅
- **합격한 테스트가 돈을 쓰고 있었다 (2026-10-07)**: [[띵동]]의 음성 인식 서비스에 일일 한도 600초를 걸어 두었는데 또 찼다. 15초 단위 과금이라 **사용량 = 성공 횟수 × 15초**가 모든 날짜에서 맞았다. 서버·터널·대시보드를 꺼 둔 날에도 호출이 찍혔다.
- **대조 실험**: 서버·터널·대시보드를 끄고(포트·프로세스 확인) 회귀 테스트만 돌린 뒤 콘솔을 봤다.

| 시점 | 성공 | 실패 | 사용량 |
|---|---|---|---|
| 실행 전 | 1 | 0 | 15초 |
| 테스트 1회 후 | 13 | 0 | 195초 |
| 테스트 2회 후 | 25 | 0 | 375초 |

  - 매번 정확히 +12건 +180초였다.
  - 첫 실행이 2초대에 끝나 "외부 왕복이면 더 걸렸을 테니 안 불렀다"고 추론했지만 틀렸다. 옮겨 쓴 왕복 시간은 4초짜리 음성으로 잰 값이었고 테스트 음성은 훨씬 짧았다.
- **원인 추적**: 저장소 밖에 네트워크 연결 시도를 기록·차단하는 장치를 두고 테스트 1회 실행 → 연결 시도 12건 = 코드상 호출 지점 12건 = 콘솔 증가 12건.

```
설정 파일을 모듈 로드 시점에 읽는다
  → 테스트용 설정이 메신저 열쇠만 비우고 음성 인식 열쇠는 안 비웠다
  → 진짜 열쇠(<REDACTED>)가 테스트 설정에 그대로 들어온다
  → 요청 처리 경로를 타는 9개 테스트가 진짜 호출
  → 성공이든 실패든 "자막 없음"으로 흡수 → 초록불
```

- **틀린 근거 표기**: 예전에 같은 의심을 "무죄"로 기록했고 근거 유형을 **실측**이라 적었는데, 실제로는 **코드 읽기**였다. "서비스를 부르는 모든 테스트가 스텁 아래 있는가"는 안 봤고 호출 수를 센 적이 없었다. 틀린 근거 표기가 판정을 실제보다 단단해 보이게 했다 → [[ai-산출물-검증]]
- **두 겹 수정**: 원인 제거(테스트 설정에서 음성 인식 열쇠 두 개를 비움) + 재발 탐지(바깥 연결을 막고 시도가 있으면 테스트 실패). 가드가 진짜 일하는지는 변형으로 확인했다 → [[fault-injection]]
  - 가드가 살아 있는지 매번 증명하는 자기검증 테스트 2개를 추가했다. 테스트 104 → 106개, 실행 2.16초 → 0.24초(참고치).
  - 합격 시험은 가드 **없이** 1회 실행 → 콘솔 25 / 0 / 375초 그대로였다(n=1).
- **지난 사용량을 테스트 실행으로 복원 (기록 70)**

| 날짜 | 복원한 실행 | 복원 건수 | 콘솔 | 판정 |
|---|---|---|---|---|
| 9/10 | 1회 | 12 | 12 | 일치 |
| 9/11 | 3회 | 36 | 36 | 일치 |
| 9/9 | 21회(코딩 에이전트가 따로 돌린 1회 포함) | 252 | 252 | 정확 일치 |
| 9/15 | — | 120~144 | 168 | 24~48건 부족 |
| 9/8 | 눈에 보이는 13회 + 숨은 실행 | 134~482 | 301 | 범위 안(미규명) |

  - 범위가 넓으면 어떤 숫자도 들어가므로 "범위 안"을 "설명됨"으로 쓰지 않았다.
  - 실행 횟수는 한 방법만 쓰면 과소계수가 된다. 직접 입력한 명령, 출력의 "Ran N" 줄, 화면에 안 보이는 캡처형 하네스, 코딩 에이전트가 따로 돌린 실행, 터미널에서 직접 돌린 실행 다섯 갈래를 합산했다.
  - "기록이 없다"고 믿었던 게 유령이었다 → [[미결-실재-확인]]
  - 이후 감시는 콘솔 일별 값으로 넘겼다. 테스트가 더는 호출하지 않으니 0이 아닌 날이 곧 신호다.

> [!warning] 모순
> 기록 69는 "하루 168건 = 테스트 14회분"을 정황으로 들었지만, 기록 70의 날짜별 복원(9/15)은 120~144건(10~12회분)만 찾아 24~48건이 부족했다. 확인 필요.
