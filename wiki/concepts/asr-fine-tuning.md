## 한 줄 정의
사전학습된 ASR 모델을 특정 도메인에 맞게 추가로 학습시키는 일이다. 이 연구에서는 [[gemma-4]]에 [[lora]]를 붙이고 [[kconfspeech]] 회의 음성으로 학습해서 짧은 발화 환각을 줄이려 했다.

**결론:** 텍스트 쪽에 붙인 LoRA는 "짧게 말하기"라는 습관을 배웠을 뿐이다. 오디오와 텍스트가 만나는 결합 지점(embed_audio)에 붙인 LoRA는 실제로 오디오를 더 듣게 만들었다.

## 핵심 내용
### 실험 질문과 전처리 원칙 (LAB 26·34)
- **실험 질문:** 파인튜닝이 모델의 **오디오 의존도**를 실제로 높이는가?
- **전처리 원칙:** 텍스트를 보기 좋게 만드는 게 목적이 아니다. 오디오 의존도를 깨끗하게 잴 수 있는 쪽으로 정했다.
  - 이중전사는 **표기형**만 남겼다. 발음형을 정답으로 쓰면 "IMF는 아이 엠 에프" 같은 표기 규칙을 외우게 되고, 이건 오디오와 상관없는 능력이다.
  - 필러(`어/ 음/`)는 **남겼다**. 오디오를 들어야만 위치를 맞출 수 있는 신호라서다.
  - 길이로 거르지 않았다. 짧은 발화를 빼면 보려는 현상 자체가 사라진다. 대신 평가를 짧은 발화(30자 이하)와 긴 발화로 나눴다.
- **데이터 분할**
  - 전체 3,588발화 중 2개 세션(S000010 뉴스 낭독 464, S000017 토크쇼 364)을 통째로 빼서 test 828로 썼다. 학습 때 못 본 화자로 평가하기 위해서다.
  - 나머지는 세션별 비율을 맞춰 train 2,485, val 275로 나눴다.
  - test 안에서 짧은 발화는 262개, 긴 발화는 566개다.
- **audio tower를 얼린 이유**
  - 오디오 인코더까지 학습하면 파라미터가 약 1억 5천만 개 늘어난다.
  - 인코더는 이미 대량 오디오로 사전학습돼 있다.
  - 환각은 LLM 쪽이 빈칸을 멋대로 채워서 생긴다고 판단했다.

### 정답 구간만 학습시키기 (LAB 26·27)
- 학습 샘플은 대화 형식으로 만든다. 사용자가 `[오디오] + "이 음성을 한국어로 전사하세요"`를 보내고 모델이 전사문으로 답하는 구조다.
- 질문까지 학습시키면 모델이 지시문을 따라 말하게 된다. 그래서 정답 구간만 라벨로 남기고 나머지는 -100으로 가렸다.
- `build_labels`는 `<|turn>`(105)과 `model`(4368)이 이어 나오는 다음 줄바꿈부터 `<turn|>`(106)까지를 라벨로 살린다.
- 커스텀 `ASRDataCollator`가 처리하는 순서는 다음과 같다.
  1. `librosa.load(sr=16000)`으로 오디오를 읽는다.
  2. 대화 형식으로 구성한다.
  3. `processor.apply_chat_template(..., padding=True)`를 적용한다. 패딩은 왼쪽에 붙고, `mm_token_type_ids` 값은 텍스트가 0, 오디오가 3이다.
  4. 마지막으로 `build_labels`를 적용한다.

### 측정: 4-way CER과 audio-gap (LAB 35)
- base와 finetuned를 같은 NF4 모델에서 비교했다. LoRA 어댑터만 켜고 꺼서 변수를 하나로 묶었다.
- 정상 오디오와 무음 오디오를 각각 넣어 4가지 CER을 잰다.
- audio-gap = CER(무음) − CER(정상)이다. 클수록 모델이 오디오에 기대고 있다는 뜻이다. → [[asr-hallucination]]

### 1차: language_model attention LoRA (LAB 35~37)

| 단계 | 짧은 발화 audio-gap | 비고 |
|---|---|---|
| base | −0.1160 | 1·2단계에서 같은 값이 재현됨 ([[reproducibility]]) |
| 소규모 480개 × 3에폭 | +0.2725 | 긴 발화 CER은 0.2422 → 0.4868로 악화 |
| 전체 2,485개 | +0.3348 | val loss 최저 3.419 |

- 숫자만 보면 좋아졌지만, 무엇이 좋아진 건지 나눠서 확인했다. 대상은 짧은 발화 262개 전수다.
  - **과생성이 줄었다.** 출력이 정답의 1.5배를 넘는 과생성 비율이 35.1%에서 1.9%로 떨어졌다.
  - **과생성을 빼면 오히려 나빠졌다.** 과생성 샘플을 제외한 167개만 비교하니 CER이 base 0.3013, finetuned 0.5210이었다.
  - **오디오를 듣지 않았다.** 오디오 길이와 출력 길이의 상관(Pearson r)은 정답 0.739, base 0.024, finetuned 0.128이었다.
  - **어려우면 회피했다.** 12자 정답을 "그렇죠"(4자)로 받아쓰는 식으로, 어려운 구간에서는 대화체 상투어를 냈다.
  - **무음에 말을 지어냈다.** 긴 발화에 무음을 넣자 "그렇죠. 그게 바로 그게 바로…" 같은 반복 루프와 상투어가 나왔다. 무음 CER은 1.9415였다.
- 결론
  - 극단적인 과생성은 억제됐다. 하지만 원했던 "오디오에 맞춘 길이 조절"이 아니라 "오디오와 무관하게 짧게 말하기"라는 prior를 배웠다.
  - 사전분포만 바꾸는 개입으로는 사전분포에 지배되는 문제를 풀 수 없다.

### 2차: 결합 지점 embed_audio LoRA (LAB 39)
- 구조는 `오디오 → audio_tower(귀) → embed_audio(결합 지점) → language_model(뇌) → 텍스트`다.
- embed_audio는 오디오 특징 1,536차원을 언어 차원 2,560으로 바꾸는 통로다. → [[audio-tower]]
- 결과(test 짧은 발화 262개)

| 조건 | 길이 상관 Pearson | 과생성 비율 | 길이 정상 샘플 CER |
|---|---|---|---|
| 정답 | +0.737 | – | – |
| base | +0.021 | 35.5% | 0.3062 |
| embed_audio LoRA | +0.755 | 3.1% | 0.2114 |

- 1차에서 보였던 역전이 사라졌다. 1차는 과생성을 빼면 finetuned가 base보다 못했는데, 이번에는 finetuned가 더 낫다. 전체 중앙값 CER도 0.4530에서 0.1914로 낮아졌다.
- base가 6자 발화에 영화 예고편 내레이션을 통째로 지어낸 샘플이 있었다(CER 72.33). 같은 샘플에서 finetuned는 CER 0.17이었다. "base는 오디오를 듣지 않고 finetuned는 듣는다"는 직접 증거다.
- 남은 오류는 대부분 발음 오인식이었다(예: "거부"를 "극복"으로 받아씀). 프롬프트로 도피하는 현상은 2자, 8자짜리 극단적으로 짧은 발화 2건에만 남았다. 이 문제는 [[audio-tower]] 실험으로 넘어갔다.

## 언제 쓰나 (상황 예시)
- 프롬프트 조정만으로 환각이 일부만 줄어들 때, 모델 쪽에서 해결하는 방법으로 쓴다.
- ASR 파인튜닝 효과를 판단할 때는 평균 CER만 보지 않는다. 무음 대조(audio-gap), 과생성 비율, 길이를 통제한 CER, 오디오와 출력 길이의 상관을 같이 본다.

## 실습에서 배운 것 / 트러블슈팅
- 첫 600개 학습은 로컬 GPU(11.94GB)에서 메모리가 부족해 중단했다. 연산 자원을 확보한 뒤 다시 진행했다.
- 단일 샘플, 긴 샘플, 배치 순서로 변환과 라벨을 확인하면 문제가 어디서 생겼는지 좁히기 쉽다.
- 평균 CER이 좋아진 건 과생성을 억제한 것만으로도 생길 수 있다. 개선이 어디서 왔는지 나눠서 확인해야 주장을 지킬 수 있다.
- 길이 상관이 높다는 것은 "길이를 맞춘다"는 뜻일 뿐이다. 과생성을 뺀 CER과 전사문 육안 확인을 함께 해야 한다.
