## 한 줄 정의
큰 데이터로 미리 학습된 모델을 가져와 내 문제에 재활용하는 방식이다. 앞부분까지 추가 학습하면 Fine-tuning이라고 부른다.

## 핵심 내용
- **세 가지 선택지 (기록 4)**

| 방식 | 하는 일 | 장점 | 단점 |
|---|---|---|---|
| Custom CNN | Conv·Pooling·FC를 직접 조합해 처음부터 학습 | 구조를 직접 설명 가능, 모델이 가벼움 | 데이터가 많이 필요, 설계 시행착오 많음 |
| Transfer Learning | 앞부분(특징 추출)은 고정, 뒷부분 FC만 새로 학습 | 적은 데이터로 높은 정확도, 학습 시간 짧음 | "왜 이 구조냐"에 "가져다 썼다"가 됨 |
| Fine-tuning | 사전학습 모델의 앞부분 레이어도 추가 학습 | Transfer Learning 수준 정확도 + 도메인 최적화 | — |

- 멜 스펙트로그램은 2D 이미지라서, 이미지 분류용으로 학습한 모델도 소리 분류에 쓸 수 있다는 게 출발 아이디어다. 오디오 전용 사전학습 모델로는 VGGish, [[yamnet]]이 있다.
- **논문 근거 (Hershey et al. 2017, ICASSP)**
  - 4.4절: AudioSet 사전학습 임베딩을 쓴 모델이 raw log-mel feature 모델보다 mAP 0.137 → 0.314였다.
  - Table 3, 클래스를 줄이면 성능이 오른다: ResNet-50 기준 30K 클래스 전체 mAP 0.212, 400 클래스 서브셋 0.381. 521개 중 3종만 분류하는 설계의 근거다.
  - Table 4, 데이터 양: 700K·7M·70M 학습 데이터의 AUC가 0.921~0.923으로 거의 같고, 70K 이하에서 성능 저하가 시작됐다. FSD50K(약 51K 클립)만으로는 부족할 수 있어 AudioSet을 보조 데이터로 추가하는 근거가 됐다.

## 언제 쓰나 (상황 예시)
- 내 데이터가 수백~수천 개 수준이고, 비슷한 도메인의 대형 사전학습 모델이 있을 때.

## 실습에서 배운 것 / 트러블슈팅
- [[띵동]]은 YAMNet을 Fine-tuning하기로 했다. 소리의 기본 특징은 사전학습 모델이 이미 알고 있으니 초인종·노크·화재경보 특화 특징만 추가 학습하는 구조다. 발표에서 "도메인에 맞게 최적화했다"고 설명할 수 있다는 점도 고려했다.
- **그대로 쓰면 도메인 클래스를 못 맞힌다**: 한국 현관 소리에서 pre-trained YAMNet Top-1은 초인종 30% / 노크 40% / 화재경보 20%였다 → [[구현-전-사전-테스트]]
- 2단계로 나눴다: 공개 데이터셋으로 1차 Fine-tuning → 클래스별 정확도 검증 → 직접 녹음을 더해 2차 Fine-tuning. 어디가 부족한지 먼저 보고 녹음으로 메운다.
- train/val/test는 **파일 단위**로 나눈다. 같은 원본에서 잘린 클립이 train과 val에 동시에 들어가면 [[data-leakage]]다.
- 예상 정확도(2026-04-28 추정): 직접 녹음 완료 시 90~93%, 없으면 75~82%.
- **예비 학습 결과 (2026-07-01)**: backbone(YAMNet)은 frozen, 위에 얹은 head만 학습했다. 학습 파라미터 131,587개 vs backbone 약 3.7M. test accuracy 0.887, recall은 초인종 74% / 노크 89% / 화재경보 92%였다.
