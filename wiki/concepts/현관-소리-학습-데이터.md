## 한 줄 정의
[[띵동]] 소리 분류 모델([[yamnet]] Fine-tuning)을 학습시키는 현관 소리 데이터다. 공개 데이터와 보드 마이크 직접 녹음을 섞어 쓰고, 출처·선별 기준·전처리 규칙·분할 방식을 함께 다룬다.

## 핵심 내용
- **소스별 수급 (2026-04-28 확정)**

| 클래스 | 소스 | 수량 | 비고 |
|---|---|---|---|
| 초인종 | FSD50K | 107 | WAV 44.1kHz, CC-BY |
| 초인종 | AudioSet | 88 | yt-dlp 실제 성공률 73% |
| 초인종 | 직접 녹음 (필수) | 90클립 예정 | 아파트 인터폰 3종 × 거리 3단계 × 10회, 문 닫힌 상태 포함 |
| 노크 | FSD50K | 270 | WAV 44.1kHz, CC-BY |
| 노크 | AudioSet | 110 | yt-dlp 실제 성공률 92% |
| 노크 | 직접 녹음 | 180클립 예정 | 문 재질 3 × 세기 3 × 거리 2 × 10회 |
| 화재경보 | AI Hub S_103 | 171 | 한국 KC 인증 단독경보형 실측 |
| 화재경보 | FSD50K Alarm 435 | 제외 | 표본 청취 결과 차량 사이렌 위주 |
| 화재경보 | AudioSet fire_alarm 100 | 제외 | RMS 분석 결과 65%가 차량 사이렌 |
| 화재경보 | 직접 녹음 (필수) | 240클립 예정 | 장소 2 × 거리 4 × 배경소음 3 × 10회 |

- **전처리 기준**: 16kHz mono 변환, 3초 고정 분할. YAMNet 입력은 raw waveform(3초 = 48,000 samples)이다. 분할은 원본 단위(아래 참고).
- **학습 파이프라인 (`ml/pipeline`)**: preprocess(16kHz mono 검증) → 원본 단위 group split → train에만 augment → 최종 조립. 입력은 `01_clips` 2,798개 → [[data-augmentation]]
- **분할 방식 (기록 82)**: `클래스 + 그룹 키`를 해시해 학습/검증/평가를 정하는 순수 함수다. 새 데이터가 들어와도 기존 배정은 안 바뀌지만, 새 그룹의 행선지는 사람이 아니라 해시가 정한다.
- **크기 맞춤(정규화, 기록 85)**: 전처리에서 모든 클립을 같은 최대 크기에 맞춘다. 조용한 보드 배경은 약 80배 증폭된다.
- **클래스 4종 (2026-10-15 4차 재학습부터)**: 초인종 · 노크 · 화재경보 · **기타 소리**. 「기타 소리」는 알림 전 맨 앞 분기에서 막혀 알림 문구까지 가지 않는다. 그래서 "분류는 4종, 알림 문구까지 가는 건 3종"이다.

## 언제 쓰나 (상황 예시)
- 공개 데이터셋의 라벨이 내 도메인과 맞는지 의심될 때. 같은 "alarm"이라도 차량 사이렌일 수 있다 → [[데이터-라벨-감사]]
- 재학습 전에 클래스 구성과 데이터 출처, 평가 쪽 배정을 확인할 때.

## 실습에서 배운 것 / 트러블슈팅
- **라벨 이름을 믿지 말고 들어 보라 (2026-04-28)**: FSD50K Alarm 1,280개를 자동 필터로 435개까지 줄였지만, 30개를 직접 들어 보니 대부분 차량 사이렌이었다. 둘 다 버리고 AI Hub 171개 + 직접 녹음으로 대체했다.
- 서양 차임벨 데이터만으로는 한국 인터폰 정확도가 60~75%로 예상됐다. 한국 아파트 단음 전자음은 공개 데이터에 거의 없어 직접 녹음이 필수였다.
- **더미 검증은 필요조건이지 충분조건이 아니다 (2026-07-01)**: 합성 더미 데이터로 각 스테이지를 검증했고 코드 리뷰도 통과했지만, 실제 데이터를 넣자 함정 4개가 나왔다.
  1. **빈 클립 → FFT 크래시**: AI Hub 원본에 길이 0인 wav 6개가 섞여 있었다. `MIN_DURATION_SEC = 0.1`(16kHz × 0.1s = 1600 samples) 가드를 두고 미달 클립은 원본을 지우지 않고 skip했다.
  2. **파일 단위 누수**: 같은 원본의 조각(`..._0000000.wav`, `_0003000.wav`)이 파일 단위 split에서 train/test로 흩어졌다. 넣어 둔 누수 방지 가드가 잡았다. "파일 단위 분할"은 실제로는 원본 단위여야 했다. 7자리 조각 접미사를 떼어 원본 키를 만들고 group split했다 → [[data-leakage]]
     - `_30.0_40.0_0000000`처럼 소수점이 든 파일명은 `Path().stem`이 소수점을 확장자로 오인한다. 순수 문자열 정규식으로 바꿨다.
  3. **stale 파일**: 고친 뒤에도 빈 클립 크래시가 재발했다. 이전 실행의 파일을 지우지 않고 덧쓰기만 해서 옛 빈 클립이 남아 있었다. write 직전에 폴더를 자동 정리하게 했다(유효 클래스 폴더 검증, 직하위 `*.wav`만 삭제) → [[reproducibility]]. 처음 세운 진단은 에이전트가 `git log -L`로 반증했다 → [[ai-산출물-검증]]
  4. **macOS TCC `EPERM`**: 데스크탑 폴더에 venv 파이썬이 접근할 때마다 권한 오류가 났다. 데이터를 홈 디렉토리로 옮겨 보호 위치를 벗어났다.
- **화재경보 앞 9초는 사람 멘트였다 (기록 76)**: 화재경보 학습분의 30.4%가 사람 안내 멘트로 시작하는 조각이라 분할 단계에서 제외했다. 그 결과 한국어 말소리 네거티브가 더 줄었다 → [[데이터-라벨-감사]]
- **모자란 두 곳 (기록 77)**: 알림 대상이 아닌 소리 중 한국어 말소리가 거의 없었고, 한국 아파트 현관 호출음을 보드 마이크로 녹음한 적이 없었다. 폰으로 녹음하면 우리 마이크의 채널 특성이라는, 구분하려던 바로 그 축이 빠진다.
- **보드 마이크 첫 초인종 녹음 (기록 77)**: 버튼을 누르면 직전 2초와 직후 5초를 노트북 수집 서버로 보낸다. 18테이크, 한 유닛·한 세션. 세션당 전송 상한은 12회이고 이후 물리 리셋이 필요하다. 녹음 절차는 코드가 아니라 로그로 확인한 동작 순서에 맞췄다 → [[구현-전-사전-테스트]]
- **무음도 학습 재료 (기록 78)**: 모델이 기기 무음 19개를 전부 노크로 분류한 뒤, 소리 없이 녹음 버튼만 누른 구간을 "기타 소리" 학습 재료로 넣기로 했다 → [[out-of-distribution]]
- **직접 녹음 (기록 80)**: 배경·노크·초인종 재생음을 랩실과 베란다에서 하루 5세트, 72테이크 수집했다. 튐 경고는 [[마이크-튐-판별]]
- **평가 칸이 비어 있었다 (기록 82)**: 재학습 전에 해시 배정을 미리 계산해 보니 보드로 녹음한 노크 6유닛, 초인종 2유닛이 전부 학습 쪽이었다. 그대로 돌렸다면 평가 숫자는 공개 데이터 노크 재현율이었다. 평가 전용 노크 유닛을 따로 녹음하기로 했다.
- **"그 외" 클래스 첫 재학습 (기록 83)**: 3클래스 모델이 목소리·가전 소리·무음까지 셋 중 하나로 우겨 넣어서 네 번째 칸을 추가했다. 학습에 들어간 조용한 현관 조각이 12개뿐이라(보드 노크 98개) 경계가 모호해졌을 수 있어, 보드를 세 자리에 두고 무음을 추가 녹음했다. 집과 랩실에서 무음 분류가 다르게 나와 장소 하나의 결과로 일반화하지 않았다.
- **학습과 서비스가 같은 소리를 다른 크기로 봤다 (기록 85)**: 가설 4개를 "지지 / 약화 / 판정 불가" 등급으로 받아 따졌다. 진짜 후보는 등급표의 "가설 밖 관찰" 칸에서 나왔다. 학습은 크기 맞춤(약 80배 증폭)한 배경을, 서비스는 원본 크기 배경을 모델에 넣고 있었다.

| 서비스 입력 처리 (4클래스 모델) | 보드 무음 오발송 |
|---|---|
| 원본 그대로 | 22 |
| 크기 맞춤 | 5 |
| 튐 주변을 뺀 최대값으로 맞춤 | 0 |

  같은 조건에서 초인종·노크·공개 시험 데이터 손실은 0이었다. 가설과 같은 방향으로 움직였다는 것까지가 결론이다 → [[모델-교체-판단]]
- **4차 재학습 전 라벨 감사 (기록 91)**: 노크 폴더 329조각을 「기타 소리」로 옮기고 라벨 없는 화재 211조각을 뺐다 → [[데이터-라벨-감사]]. 걸을 때 발소리, 노트북 내려놓는 소리가 노크로 판정되는 일이 있어 「기타 소리」 160클립(262조각)을 보강했다(헛판정 횟수 기록 없음, 효과 미측정).
- **서빙도 학습과 같은 정규화 규칙을 써야 한다 (기록 91)**: 새 모델에 원본 레벨 입력을 그대로 넣으니 보드 무음 13개 전부를 노크로 봤다.
- **16ms 무음 파일 48행 (기록 91)**: 예전 분포 밖 실험 126행 중 48행은 TTS 음성 이름을 짧게 써서 나온 16ms 무음 파일이었다. 출력 길이 검사가 없었던 탓이다. 실험 전체가 무효는 아니고, 이 48행이 사람 목소리를 노크로 오인한 사례도 아니다.
- 데모 데이터 5건에 「기타 소리」 점수 0.0을 추가했다 → [[대조-가드]]
