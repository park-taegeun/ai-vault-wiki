## 한 줄 정의
모르는 상태를 "정상"이나 "아니오" 같은 기본값으로 채우지 않고, 화면이 실제로 아는 것보다 더 많이 말하지 않게 하는 설계 원칙이다. [[띵동]]에서 시작해 [[관광데이터-공모전]]의 공공데이터 화면에도 적용했다.

## 핵심 내용
- 이 시스템의 사용자는 소리를 못 듣는다. 알림이 안 올 때 알 방법은 화면뿐이라, 가짜 "정상"은 고장을 숨기고 안심까지 시킨다.
- 반복된 사고의 원형은 하나였다: **모르는 상태를 괜찮은 상태로 채워 넣는 기본값**(코드에 박힌 가짜 숫자, 고정된 "정상" 문장).
- 고치는 방향: 기본값을 걷어내고, 모르면 모른다고 표시하고, 걷어낸 뒤 화면이 어떻게 보일지 미리 알아 둔다.
- 화면 문구도 동작 명세다. 문구가 코드보다 많이 약속하면 버그다.
- 반대 방향도 지킨다. "정상적으로 비어 있음"과 "불러오기 실패"는 다르게 보여 준다 → [[web-accessibility]], [[react]]
- 데이터 쪽에서는 **3-state**(가능 / 불가 / 정보 없음)로 나타난다. 원본 값이 비어 있는 건 "불가"가 아니다. 둘을 하나로 합치면 화면이 모르는 걸 아는 척하게 된다.

## 언제 쓰나 (상황 예시)
- 기기·서버 연결 상태를 카드로 보여 줄 때.
- 서버 응답이 끊겼는데 화면에 마지막 값이 남아 있을 때.
- 목록 문구("모든 ~")가 실제로 받는 범위와 맞는지 볼 때.

## 실습에서 배운 것 / 트러블슈팅
- **타이밍 카드 `0ms / 0%` (기록 42)**: stats가 timing을 하드코딩 0으로 반환하고 있었다. 실제 타임스탬프로 집계하게 고쳤다 → [[2단계-알림]]
- **"사람 감지됨"은 고정 문자열이었다 (기록 57)**: 센서 값이 아니라 코드에 박힌 문구였다. 센서를 안 꽂고 요청해도 같은 문구가 나와 확정했다 → [[vl53l5cx]]
- **"토큰 만료"로 보인 망 지연 (기록 84)**: 대시보드가 갱신 실패를 전부 같은 표시로 보여 줘서 망 지연과 진짜 만료가 화면에서 구분되지 않았다 → [[kakaotalk-message-api]]
- **기기 상태를 마지막 연락 시각에서 파생 (기록 89)**
  - 홈 카드에 기기가 항상 켜져 있다는 취지의 문장이 고정으로 떠 있었다.
  - 기기가 주기적으로 "살아 있다" 신호를 보내고, 화면 상태는 그 기록에서만 파생하게 했다. 마지막 연락이 90초를 넘으면 꺼짐, 신호 세기 −70dBm 이상이면 강함(둘 다 잠정값).
  - 수신 필드 5개는 전부 필수다. 하나라도 빠지면 기본값으로 채우지 않고 400으로 거절한다. 기록이 아예 없으면 "꺼짐 · 신호 없음 · 값 없음"이다.
  - 기기가 아직 신호를 안 보내서 카드는 항상 "꺼짐 · 기록 없음"이다. 회귀가 아니라 의도된 결과로, 정직해진 화면이 더 불안해 보이는 공백을 감수했다.
- **서버 연결 끊김 표시 (기록 91)**: 서버가 응답을 멈춰도 대시보드가 마지막 숫자를 정상인 척 보여 줬다. 마지막 성공 뒤 6초(잠정)가 지나면 「서버 연결 끊김」과 마지막 확인 시각을 표시하게 했다. 가짜 데이터 화면에서 1번 확인했다.
- **"감지된 모든 소리"의 거짓말 (기록 92)**
  - 실제로는 서버 기본 한 페이지 20건만 받고 다음 페이지 정보를 버리고 있었다.
  - 문구를 "최근 감지된 소리"로 고치고 숫자는 넣지 않았다. 서버 설정이 바뀌면 숫자 박힌 문구가 다시 거짓말이 된다.
  - "이전 알림 더 보기"는 20씩 늘려 최대 100까지다. 페이지 이어 붙이기는 새 알림이 들어오면 목록이 꼬여 쓰지 않았다.
  - 대가: 3초 폴링 응답이 100건 꽉 찬 행 101,456바이트, 기본 20건 20,336바이트(무압축).
  - 사진 실패 표시가 영구히 남던 것을 10초 간격 최대 6번 재시도로 바꿨다(잠정값).

### 관광데이터 공모전에서
- **null을 "아니오"로 접지 않는다**: [[찾아가는양조장-api]]의 예약 방문 가능 여부는 59곳 중 31곳(52%), 상시 방문은 9곳이 비어 있다. boolean으로 접으면 "입력 안 됨"이 "방문 불가"로 보여, 예약 가능한 곳을 불가로 표시하게 된다. 그래서 Y / N / UNKNOWN 3-state로 저장했다. 반면 전통주정보의 판매 여부는 null이 0건이라 2-state로 충분했다 → [[수기-보정-레이어]]
- **빈 칸을 기본값으로 채우지 않는다 (8/2 회의)**: 양조장 카드에 "예약 필요", "당일 방문 가능" 태그를 붙이려 했는데 정보가 없는 곳이 많았다. 선택지는 A 정보 있는 곳만 태그 표시 / B "정보 없음" 회색 태그 / C 빈 곳을 "예약 필요" 같은 기본값으로 채우기였다. C는 데이터에 없는 걸 지어내는 거라 처음부터 비추천으로 뺐다. A와 B 중 무엇을 골랐는지는 기록에 없다.
- **태그가 없는 것과 해당 없음은 다르다**: 주종 키워드가 안 걸린 양조장을 어떤 탭에도 안 넣으면 화면에서 사라진다. 59곳 중 4곳이 그랬다.
- **안내 문구가 줄 수 없는 행동을 시키지 않는다 (8/15)**: 방문 방식 표기 결과는 예약 방문 24 · 상시 방문 가능 27 · 전화 문의 필요 8곳이었는데, "전화 문의 필요" 8곳 중 2곳은 전화번호가 없었다.
- **원문 그대로는 맞고, 뽑아내면 틀린다 (수상 뱃지)**: 수상 문구를 원문 그대로 보여 주면 문제가 없다. 그런데 "대상"만 뽑으면 대회 이름에 "대상"이 들어간 경우 상을 안 받은 술에 대상 뱃지가 붙는다. "최신 1개"만 뽑아도 더 높은 옛 상이 사라지거나 술 상이 아닌 표창이 뜬다.
- **잘린 설명을 지어서 채우지 않는다**: 원본이 79자에서 문장을 끊는다. 뒷부분을 생성하는 대신 마지막 문장 경계에서 자르자고 했고, 마침표가 없어 자를 수 없는 96개는 그대로 두거나 숨기기로 했다 → [[전통주정보-api]]
- **"정형 표시는 불가능"부터 말한다**: 운영시간은 형식이 제각각이고, 견학 회차 시각(`10:30 / 14:30`)을 영업시간으로 읽으면 틀린다. `09:00 - 18:00` 틀에 끼우지 말고 여러 줄 원문이 들어온다는 전제로 영역을 잡자고 했다.
- **비는 화면을 미리 보여 준다**: 소개·체험·특징 문장·사진이 모두 없는 14곳은 이름·주소·지도·술 목록·방문 방식만 남는다. 이 상태의 화면도 디자이너가 한 번 보도록 요청했고, 연결 수단이 하나도 없는 1곳도 어떻게 보일지 따로 정해 달라고 했다.
