---
description: 커밋 전에 공개될 변경분을 분류 규칙으로 리뷰
---
공개 레포에 올라갈 변경분을 CLAUDE.md 2장 기준으로 리뷰해. **파일은 고치지 말고 커밋도 하지 마.**

1. 대상 파악: `git status --short -- wiki/ eval/`과 `git diff HEAD -- wiki/ eval/`(새 파일은 전체 내용)을 읽어.
2. 기계 검사: `python3 .tools/wiki_check.py lint`에서 🚨 항목만 가져와.
3. 의미 검사: 변경된 파일마다 정규식이 못 잡는 것을 찾아.
   - 회사·기관 이름과 지원·합격·탈락 여부, 성적·평가·점수
   - 본인 외 다른 사람의 이름과 그 사람에 관한 이야기
   - 제출 전 공모전·해커톤의 아이디어와 전략
   - 내부 URL, 계정명, 워크스페이스·프로젝트 ID, 로컬 경로에 담긴 개인정보
   - 남의 글을 길게 옮긴 부분
   - `sources`에 노출되는 원본 파일명에 담긴 정보
4. 파일마다 판정을 표로 보여줘: ✅ 공개 OK / ✂️ 일부 수정 필요 / 🔒 비공개로 이동 권장. 수정·이동이면 **어느 문장이 왜** 걸리는지 적어.
5. 마지막 줄에 "커밋해도 됨" 또는 "N건 처리 후 커밋"으로 결론을 내려. 수정은 내가 승인한 번호만 해.
