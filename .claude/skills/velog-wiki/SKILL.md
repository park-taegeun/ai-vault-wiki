# Velog → LLM Wiki 동기화

Velog는 이미 공개된 내 글이라 위키의 가장 좋은 원본이다. 이 스킬은 두 단계로 나뉜다.
**가져오기는 스크립트가(결정론적, 토큰 0), 정리는 Claude가(의미 판단).**

## 1단계 — 가져오기 (스크립트)

1. 먼저 현황을 본다.
   ```bash
   python3 .tools/velog_fetch.py --list
   ```
   시리즈별 전체/저장됨/새 글 표를 그대로 사람에게 보여준다.

2. 상황에 따라 가져온다.
   - **처음 (저장됨이 전부 0):** 한 번에 다 받지 말고 시리즈 하나씩 계획을 세워 사람에게 묻는다. 추천 순서는 글이 적고 위키 뼈대가 되는 시리즈부터.
     ```bash
     python3 .tools/velog_fetch.py --series "AI 생태계 탐험 로그"
     ```
   - **평소:** 새 글만 받는다.
     ```bash
     python3 .tools/velog_fetch.py
     ```
   - 사람이 "수정한 글도 반영해줘"라고 할 때만 `--updates`를 붙인다. (Velog 글은 발행 직후 자잘한 수정이 많아서 기본으로 켜면 원본이 불필요하게 쌓인다.)

3. 스크립트가 출력한 저장 경로 목록이 이번에 반영할 원본이다. 연결 오류가 나면 재시도하지 말고 그대로 보고한다.

## 2단계 — 반영 (Claude)

1. 새 원본이 10편 이하면 CLAUDE.md 5장 "넣기" 절차, 넘으면 `/ingest-batch` 절차로 처리한다.
2. **글 1편 = 위키 페이지 1개가 아니다.** 글은 원본이고, 위키는 그 글들에서 뽑아낸 지식이다. 연재 글 90편을 페이지 90개로 옮기면 위키가 아니라 백업이 된다.
3. 시리즈별 기본 반영 위치 (실제 시리즈 이름은 `--list` 결과로 확인):

   | 시리즈 | 주로 보강할 곳 |
   |---|---|
   | AI 생태계 탐험 로그 | `wiki/tools/` (도구별 페이지), `wiki/concepts/` (MCP, Nested Agent 등 개념) |
   | 졸업작품 기록 | `wiki/projects/` 의 졸업작품 페이지 (이력·핵심 결정), 배운 개념은 `wiki/concepts/` |
   | AI_LAB | `wiki/concepts/` (실험으로 확인한 개념과 결론) |
   | 처음 보는 시리즈 | **어디로 보낼지 사람에게 묻고**, 이 표에 추가할 줄을 제안한다 (이 파일은 사람이 고친다) |

4. 공개 글이라도 CLAUDE.md 2장을 그대로 적용한다. Velog에는 올렸어도 위키에 맞지 않는 개인 이야기는 공개 위키로 옮기지 않는다.
5. 반영한 페이지의 `## 관련`에 원글을 외부 링크로 남긴다: `- 원글: [제목](source URL)`. 공개 위키 방문자가 Velog로 넘어가는 통로가 된다.
6. `sources`에는 `_private/raw/velog/...` 경로를 남기고, `_private/log.md`에 원본 경로를 전부 기록한다.

## 3단계 — 마무리

1. `python3 .tools/wiki_check.py lint`의 🚨 항목이 0개인지 확인한다.
2. `_private/log.md`에 실행 기록을 한 줄 남긴다 (자동화 준비도 계산에 쓰인다):
   `- YYYY-MM-DD | velog-wiki | 새 글 N편 → 신규 a, 보강 b`
3. 보고: 새 글 N편 → 신규 페이지 a개, 보강 페이지 b개 (공개/비공개), 시리즈 표에 추가 제안이 있으면 그것까지.
4. 마지막에 `/publish-check`를 권한다.

## 사람이 결과를 고치라고 할 때 (중요)

지금은 **1단계(수집만 자동, 정리는 사람이 보면서)** 운영 중이다. 이 기간의 목적은 "Claude가 사람 확인 없이 정리해도 될 만큼 규칙이 안정됐는가"를 재는 것이다.

1. 이번 동기화 결과(분류, 배치한 페이지, 합친 방식, 내용)를 사람이 고쳐달라고 하면, 고친 뒤 `_private/log.md`에 한 줄 남긴다:
   `- YYYY-MM-DD | correction | velog-wiki | 무엇을 왜 고쳤는지 한 줄`
2. 단순 오타나 사람의 취향 변경은 기록하지 않는다. **Claude의 판단이 틀린 경우만** 기록한다.
3. 같은 종류의 수정이 두 번 나오면, 시리즈 표나 CLAUDE.md에 넣을 규칙 한 줄을 제안한다 (사람이 고친다).
4. 준비도는 `python3 .tools/wiki_check.py lint` 맨 아래 "자동화 2단계 준비도"에서 확인한다.
