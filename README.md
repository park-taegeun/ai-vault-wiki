# AI-Vault — LLM Wiki

AI가 직접 읽고, 정리하고, 유지하는 개인 지식 위키입니다.
안드레 카파시(Andrej Karpathy)가 공개한 **LLM Wiki** 패턴을 Obsidian + Claude Code로 구현했고, 공개 위키는 Quartz로 웹사이트까지 배포합니다.

- **Obsidian** — 마크다운 파일을 보는 화면 (그래프 뷰, 링크 탐색)
- **Claude Code** — 볼트 폴더에서 직접 파일을 만들고 고치는 사서 에이전트
- **CLAUDE.md** — 위키를 어떻게 정리·유지할지 정의한 규칙서
- **Quartz** — 공개 위키를 그래프 뷰가 있는 정적 사이트로 빌드
- **[obsidian-skills](https://github.com/kepano/obsidian-skills)** — Obsidian 공식 에이전트 스킬 (markdown, bases)

## 구조

| 층 | 경로 | 어디에 |
|---|---|---|
| 1층 원본 | `_private/raw/` | 비공개 레포 |
| 2층 공개 위키 | `wiki/` | 이 레포 + 웹사이트 |
| 2층 비공개 위키 | `_private/wiki/` | 비공개 레포 |
| 3층 규칙서 | `CLAUDE.md` | 이 레포 |
| 품질 측정 | `eval/` | 이 레포 + 웹사이트 |

점검 스크립트와 배포 설정은 숨김 폴더 `.tools/`에 있어서 Obsidian 사이드바에는 노트 폴더만 보입니다.

볼트 하나 안에 레포가 두 개입니다. 이 레포는 `_private/`를 통째로 무시하고, `_private/`는 그 자체로 별도 private 레포입니다.

## 명령어

| 명령어 | 하는 일 |
|---|---|
| `/ingest <경로>` | 원본을 읽고 위키 페이지를 만들거나 보강, 교차참조, 목차 갱신 |
| `/ingest-batch` | 서브에이전트가 병렬로 초안을 쓰고, 메인 에이전트 혼자 병합 (단일 작성자) |
| `/capture <메모>` | 한 줄 메모를 원본으로 저장하고 관련 프로젝트 페이지에 바로 반영 |
| `/query <질문>` | 위키 페이지를 근거로 `[[링크]]` 인용하며 답변 |
| `/lint` | 스크립트 점검 + Claude의 의미 판단(모순·중복)으로 위키 정비 |
| `/status` | 프로젝트·취업 현황 대시보드 |
| `/publish-check` | 커밋 전, 정규식이 못 잡는 분류 실수를 Claude가 리뷰 |
| `/eval` | 골든 질문으로 위키 품질을 측정하고 추이를 기록 |
| `/notion-sync <페이지>` | Notion MCP로 노션 페이지를 원본으로 가져오기 |
| `/velog-wiki` | 내 Velog 새 글을 가져와 위키에 반영 (스킬, 수집은 `.tools/velog_fetch.py`) |
| `/dashboard` | Obsidian 안에서 늘 보이는 프로젝트 대시보드(`.base`) 생성 |

## 운영 단계 — Velog 자동화

"손으로 해서 안정된 과정만 자동화한다"는 원칙에 따라 두 단계로 나눠 운영합니다.

| 단계 | 자동으로 하는 일 | 사람이 하는 일 |
|---|---|---|
| **1단계 (현재)** | 매일 새 글을 원본 창고에 수집 (`.tools/velog_schedule.sh`, AI 사용 안 함), 새 글·실패 시 Mac 알림 | `/velog-wiki`로 정리하며 결과 확인, Claude 판단이 틀리면 고치고 기록 |
| 2단계 (조건 충족 시) | 수집 + 위키 정리까지 | 요약 알림 확인, `/publish-check` 후 push |

전환 기준은 감이 아니라 숫자로 봅니다. `/lint` 맨 아래의 **자동화 2단계 준비도**가 최근 14일간 `/velog-wiki` 실행 5회 이상, 사람이 판단 오류를 고친 횟수 1회 이하이면 전환을 검토합니다. 수집이 3일 넘게 멈추면 `/lint`가 경고합니다.

## 설계 원칙

**1. 규칙(soft)과 강제(hard)를 분리한다.**
`CLAUDE.md`는 모델에게 하는 부탁이라 어겨질 수 있습니다. 어기면 사고가 나는 규칙은 시스템이 막습니다.

| 시점 | 장치 | 막는 것 |
|---|---|---|
| 쓰는 순간 | `.claude/hooks/guard.py` (Claude Code PreToolUse 훅) | 원본 수정, 공개 구역에 비밀값·개인정보 쓰기 |
| 권한 | `.claude/settings.json` deny | push, 훅 우회, 가드·스크립트 자기 수정 |
| 공개 커밋 | `.githooks/pre-commit` | 비공개 경로, 비밀값·개인정보, 공개→비공개 링크 |
| 비공개 커밋 | `_private/.githooks/pre-commit` | 살아 있는 API 키·토큰 |
| 배포 | `.github/workflows/publish.yml` | 공개 파일 전수 재검사, 실패 시 배포 중단 |

**2. 답이 정해진 일은 코드가, 판단이 필요한 일은 LLM이 한다.**
링크 개수·마감일 계산·미처리 원본 찾기는 `.tools/wiki_check.py`가 결정론적으로 처리하고, Claude는 모순·중복·분류 같은 의미 판단만 맡습니다.

**3. 병렬로 쓰되, 공유 상태는 한 명만 고친다.**
대량 이관 때 서브에이전트들은 초안만 쓰고, 목차·로그·위키 병합은 메인 에이전트 하나가 합니다. 여러 에이전트가 같은 파일을 동시에 고쳐 서로의 수정을 덮어쓰는 문제를 구조로 막습니다.

**4. "복리로 똑똑해진다"를 측정한다.**
고정된 골든 질문을 질문마다 새 에이전트로 답하게 해서 검색 적중·사실 정확·위키만으로 답함을 채점하고, 위키 크기와 함께 추이(`eval/results.md`)를 기록합니다.

> 클론해서 쓸 때는 `git config core.hooksPath .githooks`로 커밋 훅을 연결하세요 (Git은 훅 설정을 클론으로 옮기지 않습니다).
